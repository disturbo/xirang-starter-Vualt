# Publish Wiki

1. Work from verified summaries and current project facts, not from an unreviewed source dump.
2. Select the correct destination: project content in `10-项目/`, shared material in `20-资料/`, stable rules in `30-规范/`, decisions in `40-决策/`, and reusable experience in `50-经验/`.
3. Lead with the current conclusion, then provide evidence, impact, unresolved items, and next actions.
4. Add only useful frontmatter. Distinguish `draft`, `current`, `deprecated`, and `archived` accurately.
5. Link the artifact from an existing MOC, project README, or stable topic page so it is not orphaned.
6. Preserve source links and dates. Label inference and uncertainty instead of converting them into facts.
7. When project-specific rules conflict with a generic template, the current authorized project rule wins within its scope.

Publishing here means maintaining a knowledge artifact. It does not authorize external sending, website publication, or production deployment.
