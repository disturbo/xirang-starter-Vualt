# 息壤基建与工作平台边界

## 结论

“息壤”有一个治理内核，但不是所有承载息壤工作的东西都属于息壤基建。以后先按对象改变的行为和生命周期分类，再决定是否进入发布清单、是否长期保存。

| 层 | 定义 | 典型路径/对象 | 保存与发布规则 |
|---|---|---|---|
| 息壤基建 | 决定授权、范围、状态、证据、验收、恢复或发布安全的控制面 | `.xirang/`、`.standards/`、Hook、StateStore schema/CLI、门禁、正式测试、根 `AGENTS.md` | 版本化；代码与测试长期保留；纳入基建发布清单 |
| 息壤工作平台 | 承载人和 Agent 使用基建的宿主或适配面 | Codex、Claude、Obsidian、飞书、浏览器、平台适配配置 | 只在真实安装并通过当前 canary 后报告已接通；平台版本不等于基建版本 |
| 任务产物 | 为某次实现、测试、审查或交付临时生成的材料 | 临时目录、候选 ZIP、一次性审查报告、证据导出、截图、测试日志 | 证据进入 StateStore/Git/正式交付后清理实时副本；不进入长期基建清单 |
| 业务内容 | 使用平台完成的项目资料与产品成果 | `10-项目/`、PRD、原型、业务决策、资料摘要 | 按业务规范治理；不能混进息壤基建发布 |

## 四个判定问题

依次判断：

1. 删除它会不会改变授权、门禁、状态机、证据、验收、恢复或发布安全？会：基建。
2. 它是否只是让基建在某个宿主上可用？是：工作平台或适配层。
3. 它是否只证明某次任务做过什么，且权威证据已进入 StateStore/Git/交付记录？是：任务产物。
4. 它是否描述业务而不是治理系统？是：业务内容。

文件名含“息壤”不是分类依据；目录位于 `.standards/tests/` 的正式自动化测试是基建，测试运行产生的 `tmp*`、报告和导出不是。

## 发布边界

基建发布清单可以包含：机器契约、适配器、门禁与状态实现、与实现绑定的自动化测试、必要运维/回滚入口、包清单与哈希。

基建发布清单不应包含：某次任务的对抗审查报告或执行矩阵、运行时临时目录与缓存、业务内容、未验真的平台配置、旧方法论全集。

## 生命周期

- 源码与测试：Git 长期保存。
- 权威运行状态：StateStore 保存，Markdown/JSONL 仅作投影或导出。
- 当前说明：只保留少量 `status: current` 文档。
- 历史设计：需要时从 Git 历史取回，不在实时 Vault 维护重复搜索面。
- 临时测试数据：正常结束自动删除；进程崩溃由下一次 recover/启动清理。
- 一次性报告：交付绑定完成后删除实时副本，不得反向成为运行真源。

## 后续强制动作

- 开工时标注任务属于四层中的哪一层。
- 修改基建走控制面维护；修改业务内容走普通内容任务。
- 平台“有配置”只能报告 configured；六项行为证据齐全才报告 connected。
- 审查结束时检查：源码/测试保留，临时数据/报告/缓存清理。
- 不以文件名判断保留；看它是可复用实现还是一次性运行产物。
