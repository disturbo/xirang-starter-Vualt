# 通用 PRD 输出规范

## 最小章节

1. 背景与目标
2. 用户与使用场景
3. 范围与排除项
4. 参与者、角色与权限
5. 业务流程、状态和规则
6. 功能需求、交互、数据、异常恢复与验收

## 每项需求至少讲清

- 谁在什么场景下使用。
- 触发条件、输入、处理和输出。
- 正常流程、空状态、错误和恢复。
- 谁可以查看、创建、修改、审批或删除。
- 哪些条件满足才算交付完成。

每个关键功能使用同一闭环：触发者与前置条件 → 输入与校验 → 系统处理 → 状态变化 → 输出与通知 → 失败、重试和恢复 → 权限与审计 → 可测试验收条件。只有页面描述、字段列表或“支持某功能”不能算完整需求。

## 状态、数据与异常

- 状态表至少包含状态码、名称、进入条件、允许操作、出口、终态与异常恢复；流程图与正文必须使用同一名称。
- 数据项说明来源、是否必填、校验、可见范围、编辑者、保留与删除影响；敏感数据说明最小权限和脱敏。
- 明确空状态、重复提交、超时、并发冲突、外部依赖失败、部分成功、撤销或补偿路径；无法自动恢复时说明人工介入和证据。

## 验收写法

验收条件应能被独立验证，使用“给定前置条件—执行动作—观察结果”的形式，覆盖主流程、权限拒绝、校验错误、异常恢复和关键状态迁移。未确认规则单独进入待确认清单，不用假设补齐。

## 输出要求

- 业务语言优先，技术实现只写到影响产品判断的程度。
- 状态、角色、字段和规则使用一致名称。
- 流程图与正文必须表达同一语义。
- 未确认内容明确标注，不编造结论。
- 项目专项规范高于本通用规范，并应放在项目目录中。
