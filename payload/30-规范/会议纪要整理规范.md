# 会议纪要整理规范

会议纪要用于保存已经发生的讨论、决定和待办，不是逐字稿的简单复制。

## 必须包含

- 会议主题、日期和参与角色。
- 背景与需要解决的问题。
- 已确认结论。
- 未确认事项及其负责人。
- 待办、截止时间和验收方式。
- 相关资料与决策链接。

## 整理原则

1. 原话与整理后的判断分开。
2. 没有明确决定时写“待确认”，不要替参会人作决定。
3. 待办必须有动作、责任人或责任角色和完成条件。
4. 涉及长期有效的选择时，另建决策记录并互相链接。
5. 不在纪要中保存会议链接里的访问凭证、个人联系方式或账号信息。

## 飞书来源的处理

1. 先判断对象类型：Wiki 节点只负责定位；正文读取使用云文档；妙记使用 Minutes；已知 `note_id` 的会议纪要使用 Note；历史视频会议记录使用 VC。不要把所有飞书链接都当作普通网页或 Docx。
2. 先只读取得标题、会议实际日期、原始 token/URL、来源类型和可用正文，再整理内容。链接本身不是“已读取”的证据。
3. 原始逐字记录、飞书自动摘要和 Agent 整理结论分层标识；不得把自动摘要冒充参会人原话。
4. Frontmatter 使用 `meeting_date` 记录实际召开日期，使用 `source`、`source_type` 和 `source_url` 记录来源；未知信息省略，不猜测。
5. 附件、画板、表格和图片应保留来源关系；需要画流程图时同时遵循 [[流程图绘制规范]]，正式飞书画板必须回读原生对象并验收。
6. 重复导入前按来源 token/URL、会议日期和主题检查；同一来源更新时记录更新时间，不静默创建多个真源。

## 推荐 Frontmatter

```yaml
---
title: 会议主题
meeting_date: YYYY-MM-DD
type: 会议纪要
source: 飞书妙记或其他来源描述
source_type: feishu_minutes|feishu_note|feishu_doc|local_file|manual
source_url: https://example.invalid/source
status: 待评审
---
```
