# SVG架构图设计规范

本规范用于知识库中的分层架构、能力地图、组件关系和信息总览。SVG负责解释结构和关系；有严格业务顺序、判断或泳道时，应改用 [[流程图绘制规范]]。

## 1. 交付边界

- 正式源文件是可读、可维护的独立 `.svg`；
- Markdown只负责嵌入和解释，不复制第二份图内事实；
- PNG可以作为预览，不能替代SVG源文件；
- 不从PPT、设计工具或网页直接导出大量不可维护的路径噪声；
- 图中的版本、数量和状态必须能回到权威正文，不在图里建立第二真源。

## 2. 先写信息模型

动手前先明确：

```yaml
title: 图要回答的问题
audience: 主要读者
layers:
  - id: layer-a
    name: 层名称
components:
  - id: component-a
    layer: layer-a
    label: 组件名称
relations:
  - source: component-a
    target: component-b
    type: main|feedback|data|constraint
```

一张图只回答一个主要问题。内容超过一屏仍无法说清时，拆成总览图和专项图。

## 3. 画布与布局

- 推荐基础宽度1280px，四周安全边距至少40px；
- 使用 `viewBox` 提供响应式缩放，不依赖固定显示宽高；
- 主阅读方向从上到下或从左到右，只选择一种；
- 层与层之间至少24px，卡片之间至少14px；
- 同一行卡片顶部、底部和中心线保持一致；
- 每一层最右侧边界对齐，避免锯齿式收尾；
- 标题区、内容区和图例区物理分离；
- 任何元素不得越过画布安全边距。

## 4. 字体与文字

使用跨平台系统字体：

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI",
             "PingFang SC", "Microsoft YaHei", Arial, sans-serif;
```

| 元素 | 建议字号 |
|---|---:|
| 主标题 | 28–32px，粗体 |
| 副标题 | 14–16px |
| 层标题 | 16–18px，粗体 |
| 卡片标题 | 14–16px，粗体 |
| 正文 | 12–14px |
| 图例和辅助文字 | 不小于11px |

规则：

- 每行文字保持短句，长内容回到正文；
- 中文文字不使用`letter-spacing`；
- 每行使用独立的坐标，不把多个`text`叠在同一点；
- 重要语义不能只写进`title`或悬浮提示；
- 不使用依赖单一操作系统的特殊字体。

## 5. 色彩与对比度

默认使用中性设计令牌：

| 角色 | 建议色值 |
|---|---|
| 页面背景 | `#F8FAFC` |
| 卡片背景 | `#FFFFFF` |
| 主文字 | `#1F2937` |
| 次文字 | `#64748B` |
| 边框 | `#CBD5E1` |
| 主关系 | `#334155` |
| 数据关系 | `#2563EB` |
| 正向状态 | `#15803D` |
| 警告 | `#A16207` |
| 异常 | `#B91C1C` |

- 正文与背景对比度至少4.5:1；
- 深色背景不承载小号中文；
- 高饱和色只用于窄色条、描边、箭头或小型状态标识；
- 红、绿、黄之外再用形状或文字表达语义，兼顾色觉差异；
- 具体项目存在上位品牌规范时才覆盖默认令牌。

## 6. 卡片与分层

每一层使用浅色底衬和清楚边框。卡片使用少量统一规格：

- 圆角6–10px；
- 内边距至少14px；
- 标题与第一段内容间距至少12px；
- 内容块之间至少18px；
- 卡片底部保留至少14px；
- 同层卡片使用相同标题位置和内边距。

父层必须完整包围子卡片。状态徽标放在标题附近或卡片外侧，不覆盖正文。

## 7. 连线与箭头

只使用少量明确关系：

| 类型 | 样式 |
|---|---|
| 主关系 | 深色实线，2px |
| 数据关系 | 蓝色实线，1.5–2px |
| 反馈 | 灰色或警示色虚线 |
| 约束 | 灰色点划线 |

规则：

1. 连线不得穿过卡片或文字；
2. 箭头终点落在目标边界，平行线间距至少10px；
3. 独立SVG可使用`marker`，但ID必须唯一、箭头颜色与线一致；
4. 作为网页内联SVG时优先使用显式多边形箭头，避免多个图的`marker` ID冲突；
5. 用于连线的`path`必须显式写`fill="none"`；
6. 复杂反馈线走外围通道，不包围无关卡片。

## 8. 可访问性与安全

- 根`svg`包含`role="img"`、`aria-labelledby`、`title`和`desc`；
- 所有ID使用稳定前缀，避免同页多个SVG冲突；
- 不嵌入脚本、外部页面、远程字体、跟踪像素或外链图片；
- 不写个人姓名、本机路径、账号、密钥或项目机密；
- 图中的链接只能指向明确允许的文档或公开来源。

示例骨架：

```xml
<svg xmlns="http://www.w3.org/2000/svg"
     viewBox="0 0 1280 720"
     role="img" aria-labelledby="diagram-title diagram-desc">
  <title id="diagram-title">架构图标题</title>
  <desc id="diagram-desc">一句话说明图的层级和主要关系</desc>
  <!-- 背景、分层、卡片、连线、图例 -->
</svg>
```

## 9. 验收

写完必须真实渲染，不以XML可解析代替视觉通过。

- [ ] XML解析无错误，没有脚本和外部资源；
- [ ] 标题、层级、卡片和关系与权威正文一致；
- [ ] 常用阅读宽度下正文仍清楚；
- [ ] 没有文字溢出、元素重叠、边缘裁切和灰底灰字；
- [ ] 所有卡片位于父层内，层间和卡片间距达标；
- [ ] 连线不穿卡片，箭头方向和图例一致；
- [ ] 深浅主题或目标背景下没有不可读内容；
- [ ] SVG源文件与嵌入预览是同一版本；
- [ ] 图的结论能回到正文或数据来源。

任何未执行的渲染环境或对比度检查都要明确列为未验证项。
