# 5步工作流

> 示例项目 EXAMPLE 单模块推进标准流程
> 来源：[[00-示例项目EXAMPLE-整体推进计划]]
> v1.1 更新：嵌入 3 个增强点（启动问卷 / 阶段化进度 / 逻辑确认稿），流程骨架不变。

---

## 流程图

```
Step 1 · RAG检索 → 资料摘要
  📥 从本地资料抽取相关内容
  📄 产出：{模块}/资料摘要.md
        ↓
  ┌─────────────────────────────────────────────┐
  │ 🔍 Step 1.5 · 模块启动问卷（增强）          │
  │                                             │
  │   触发：资料摘要完成后、设计方案开始前       │
  │   做法：AI 读取 资料摘要 + README + 差异点   │
  │         动态生成 5-8 个模块专属业务问题      │
  │   产出：回答追加到 资料摘要.md ## 启动问卷   │
  │                                             │
  │   跳过条件：资料摘要已含飞书源全文 +         │
  │   评审纪要 ≥ 2份 → 标注理由后可跳过         │
  └─────────────────────────────────────────────┘
        ↓
Step 2 · 设计方案（需评审）
  🎨 业务流程图 + 角色权限 + 状态机 + 字段清单 + 页面清单

  📊 阶段化 checkpoint（增强）：
     每完成一个主动向产品负责人汇报进度——
     □ 2a · 字段定义与数据说明
     □ 2b · 状态机与流程图
     □ 2c · 交互规则与页面清单
     □ 2d · 角色权限矩阵
     □ 2e · 异常场景与非功能需求

     失败可精确回溯到具体 checkpoint，
     而非"设计方案不行，全部重来"。

  📄 产出：{模块}/设计方案.md
        ↓
Step 3 · 方案确认 ⏸
  👤 你的反馈 → 迭代方案
        ↓
  ┌─────────────────────────────────────────────┐
  │ 📋 Step 3.5 · 逻辑确认稿（增强）            │
  │                                             │
  │   触发：设计方案确认通过后、原型开始前       │
  │   做法：生成"页面 × 字段 × 操作"映射表      │
  │         聚焦产品逻辑，禁止讨论视觉           │
  │   确认：产品负责人逐页 ✅ 或标注修改意见     │
  │         全部 ✅ 后方可进入 Step 4             │
  │   产出：{模块}/逻辑确认稿.md                 │
  │                                             │
  │   失败回溯：原型评审发现逻辑缺陷时，         │
  │   回到逻辑确认稿定位遗漏行 → 精确修正       │
  └─────────────────────────────────────────────┘
        ↓
Step 4 · 原型产出
  🖥 按页面清单逐个产出 HTML（共用 [[原型输出规范|common.css]]）
  📄 产出：prototype/pages/{模块}/*.html
        ↓
Step 5 · PRD产出
  📝 基于设计方案 + 原型 → 完整 PRD
  📄 产出：docs/{序号}-{模块}-PRD.md（遵循 [[示例项目PRD硬约束-v3.3]]）
```

## 三个增强点速查

| 增强 | 位置 | 解决什么问题 | 约束详见 |
|------|------|-------------|---------|
| **模块启动问卷** | Step 1 → 2 之间 | 需求收敛——不再"一句话直接跳到 PRD 模板" | [[示例项目PRD硬约束-v3.3]] §9 |
| **阶段化 checkpoint** | Step 2 内部 | 进度透明——draft 10% 和 90% 不再看起来一样 | 本文 Step 2 清单 |
| **逻辑确认稿** | Step 3 → 4 之间 | 逻辑验证——评审聚焦产品逻辑，不沦为审美讨论 | [[示例项目PRD硬约束-v3.3]] §10 |

> **设计来源**：Claude Design 3×10 步方法论 + Hermes / Claudian联合分析。
> 详见 [[Claude Design 工作流分析与示例项目项目借鉴 1]]。

## 每模块交付包

```
outputs/示例项目EXAMPLE/
├── docs/
│   ├── {序号}-{模块}-资料摘要.md     ← Step 1 + 1.5
│   ├── {序号}-{模块}-设计方案.md     ← Step 2（含 checkpoint 记录）
│   ├── {序号}-{模块}-逻辑确认稿.md   ← Step 3.5（新增）
│   └── {序号}-{模块}-PRD.md          ← Step 5
└── prototype/pages/{模块}/
    ├── {模块}-list.html               ← Step 4
    ├── {模块}-detail.html
    └── ...
```
