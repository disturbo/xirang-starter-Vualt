# SVG 架构图设计规范 v1.4

> 适用范围：vault 内方法论、决策、规范类文档的手工 SVG 配图（如 [[多智能体协作方法论-v5-架构图]]）。
> 不适用：自动导出图（PPT/Figma/Excalidraw 导出），那些走 PNG 截图通道。

---

## 1 · 为什么用 SVG 不是 Mermaid 不是截图

| 方案 | 适用 | 不适用 |
|---|---|---|
| Mermaid | 流程图、状态机、依赖图 | 多区域综合大图、卡片化 KPI、视觉品质要求高的总架构图 |
| **SVG（本规范）** | **总架构图、综合仪表盘、对外展示** | 频繁迭代的工作流图（改起来比 Mermaid 慢） |
| PPT/Figma 截图 | 一次性汇报、外部分享 | 知识库长期维护（PNG 不能 git diff） |

判定优先级：能用 Mermaid 解决的优先 Mermaid。Mermaid 撑不起来的再写 SVG。

## 2 · 文件存放与命名

### 路径

| 类型 | 路径 |
|---|---|
| 方法论配图 | `50-经验/{方法论名}-架构图.svg` |
| 决策配图 | `40-决策/{决策ID}-{主题}.svg` |
| 其他位置 | ❌ 不允许（会被 .gitignore 拦截） |

### 命名

```
{源文档名}-{图类型}.svg

✅ 多智能体协作方法论-v5-架构图.svg
✅ GBrain+LLM-Wiki-范式借鉴-数据流.svg
❌ 架构图.svg            （没主题，不可识别）
❌ untitled.svg          （从设计软件导出的默认名）
❌ diagram-final-v2.svg  （final / v2 这类版本词不要进文件名）
```

### .gitignore 例外

vault 根 `.gitignore` 默认拦截所有 SVG（防 PPT/Figma 导出污染），仅以下两个目录例外：

```
!50-经验/*.svg
!40-决策/*.svg
```

放到其他位置的 SVG **不会进 git**——Obsidian 本地能渲染，但其他人 clone 拿不到。

## 3 · 视觉系统

### 3.1 画布

| 用途 | 推荐尺寸 | viewBox |
|---|---|---|
| 总架构图（4 层综合） | 1280 × 1500-1600 | `0 0 1280 {h}` |
| 单概念图（数据流/状态机） | 800 × 600 | `0 0 800 600` |
| 横版对比图 | 1280 × 800 | `0 0 1280 800` |

**不要硬编码 width/height 属性**——只写 `viewBox`，让浏览器/Obsidian 自适应宽度。

## 4 · 间距与防重叠（重点，本规范的核心约束）v1.2

### 4.1 行距

| 字号 | 最小行距 | 推荐行距 |
|---|---|---|
| 11px | 14px | 16px |
| 12px | 16px | 18px |
| 14px | 18px | 20px |
| 16px | 20px | 24px |
| 22px | 28px | 32px |

中文字符的实际渲染高度比 font-size 大 ~30%（line-height ≈ 1.3），SVG 里 `<text>` 默认无行距，必须靠 `y` 坐标手动控制。

### 4.2 卡片内 padding

| 卡片高度 | 顶/底 padding | 左/右 padding |
|---|---|---|
| ≤120px | 16px | 16px |
| 120-300px | 20px | 20-24px |
| ≥300px | 24px | 24-28px |

**4.2.1 文字至边框最小距离**（2026-05-17 新增）：任何卡片内的文字元素，其左/右/上/下边界距卡片内边至少 **12px**。严禁文字贴边框或仅留 2-4px 窄缝。

### 4.3 元素间距

| 关系 | 最小间距 |
|---|---|
| 两个并列卡片 | 14px |
| 标题 → 内容 | 24px |
| 内容块 → 下一个内容块 | 22px ⚠️ 本规范的硬约束 |
| 卡片 → 卡片底边 | 16px |
| 箭头起点 → 卡片边 | 5-10px |

### 4.4 防重叠检查清单（写完必跑）

每一块内容（标题、列表、子卡片）都要算清楚：

```
内容块顶 y = transform.y + 内部相对 y
内容块底 y = 顶 y + (font-size × 行数) + (行距 × (行数-1))

下一块顶 y ≥ 上一块底 y + 22 (内容块间距硬约束)
```

**踩过的坑（v5 架构图首版）**：
- Vault 主卡里"三层资料卡片"高 100，相对 y 88-188
- "目录布局" g translate(20,**160**) → 标题在 y=174，**重叠 14px**
- "防污染规则" g translate(20,**250**) → 跟目录内容延伸到 252 又重叠

修复后：目录布局改到 y=210，防污染改到 y=340，整卡高度 320 → 410。

> 💡 写完用浏览器或 Obsidian 实际渲染一遍，肉眼检查每一块。SVG 在文本编辑器里看不出重叠，必须渲染。

### 4.5 Obsidian 渲染验证

```bash
# 1. 在 Obsidian 里新建一个临时笔记，引用 SVG
echo '![[你的SVG.svg]]' > /tmp/svg-test.md

# 2. 打开 Obsidian 阅读模式查看
# 3. 检查每个文字块是否清晰、是否重叠、emoji 是否对齐
```

### 4.6 色彩对比度与饱和度规则（2026-05-17 新增，v1.2 强化）

**核心原则**：高饱和度颜色（如 `#861B2F` 品牌红、`#dc2626` 警示红）**禁止作为大面积背景**承载浅色文字。中文小字在深色背景上渲染模糊，对比度不足，Obsidian 截图后识别度极低。

| 规则 | 说明 |
|---|---|
| 4.6.1 | 高饱和度颜色（R+G+B < 200 且某一通道 > 其他两通道均值 × 1.5）**只能用于**：描边、顶部色条（≤40px 高）、箭头、徽标、图标。**禁止**用于 ≥ 50px 高的背景区 |
| 4.6.2 | 承载文字的色块必须满足 **WCAG AA 对比度 4.5:1**。深色背景（`#1f2937`/`#374151`）上的文字用 `#ffffff` 或 `#f3f4f6`；浅色背景（`#ffffff`/`#f9fafb`）上的文字用 `#1a1a1a` 或 `#374151` |
| 4.6.3 | 标题栏用品牌色做**窄色条**（高 ≤ 40px）+ 下方浅色内容区，而不是整个标题栏灌满品牌色 |
| 4.6.4 | 中文字号 ≤ 14px 时，**禁止**放在任何深色（`L < 40%` 亮度）背景上——iOS Safari 小字在深色底上抗锯齿加倍模糊 |
| 4.6.5 | **卡片标题栏暗色禁令**（v1.2 新增）：`#1f2937`、`#1e293b`、`#0f172a` 等深灰/黑色**禁止**用于卡片标题栏背景——即使是白字，10-12px 中文在深色栏上渲染对比度不足，截图后几乎无法辨认。替代方案：① 用该卡片主题色的浅色版（如 `#F5A623` → `#FFF3E0`）配深色文字；② 或用主题色窄条（≤8px）+ 白色主体区 |
| 4.6.6 | **标题栏底部不得出现异色细线**（v1.2 新增）：品牌色窄条（`#861B2F` 40px）与下方渐变背景交界处，必须确保颜色均匀过渡。方案：在色条正下方加一层同色 2px 矩形覆盖交界线，或整个标题区放纯色底衬 |

### 4.7 右侧边缘对齐规则（2026-05-17 新增，v1.3 强化）

**核心原则**：右边距 40px 与左边距同等严格。任何元素的右边界 x + width **必须 ≤ viewBox-width - 40**。

| 规则 | 说明 |
|---|---|
| 4.7.1 | 写每块 `<g transform>` 前计算：`可用宽度 = 1280 - 40(左) - 40(右) - 层标签(80) = 1120`。卡片宽度 + 起点 x ≤ 1120 |
| 4.7.2 | 文本元素右侧必须留 ≥ 20px 呼吸空间。禁止 `x="W-15"` text-anchor="end" 贴边 |
| 4.7.3 | **自检**：写完后 grep 所有 `x="`、`width="`，确认没有任何 `x + width > 1240` |
| 4.7.4 | **跨层右边缘对齐（v1.3 新增）**：一张架构图中，所有层的**最右侧卡片右边缘必须在同一条垂直线上**（公差 ≤ 6px）。不允许出现「传输层卡片右边缘 1196px，原子层右边缘 1226px」这种 30px 锯齿差。做法：选一个目标右边缘（推荐 1220），所有层的最右侧卡片 `x = 1220 - width` |

### 4.8 标题区多行规则（2026-05-17 新增）

| 规则 | 说明 |
|---|---|
| 4.8.1 | 标题区（含主标题 + 副标题 + KPI 栏）**至少 3 行**，禁止单行堆砌 ≥ 3 个概念 |
| 4.8.2 | 副标题每行 ≤ 80 字，超过必须换行。禁止在一行里塞 6 个通信模式 + 传输层 + 3 个对标协议 |
| 4.8.3 | 主标题含版本号时分离：主标题 32px bold，版本号用 14px 灰色次级标注，不要挤在同一行 |

### 4.9 层级视觉区分规则（2026-05-17 新增）

| 规则 | 说明 |
|---|---|
| 4.9.1 | 每个架构层（如原子层/协议层/传输层）必须有**独立的浅色底衬**（`fill="#f9fafb"` 或 `#f0f4f8`）和 **≥ 1px 边框**（`stroke="#e5e7eb"`），让层与层之间在视觉上可区分 |
| 4.9.2 | 层标签放在**层底衬的左上角**，用浅色背景上的深色文字（不要用深色标签条+白字） |
| 4.9.3 | 层与层之间的间距 ≥ 24px，绝不允许两个层的底衬紧贴或重叠

### 4.10 元素溢出防护规则（2026-05-17 新增，v1.3 强化）

**核心原则**：任何文字/标签元素必须被其父级容器完整包围，不得有一行文字、一个像素伸出容器边界。

| 规则 | 说明 |
|---|---|
| 4.10.1 | 写每个 `<text>` 前计算：`文字底部 y = text.y + font-size × 1.2`。该 y 值必须 ≤ `容器.y + 容器.height - min(12, 容器高度×0.1)` |
| 4.10.2 | KPI 数值（`kpi-num` 28px）在 42px 高的 KPI 栏中必须调低字号至 ≤ 22px，或 KPI 栏高度 ≥ 52px |
| 4.10.3 | 层底衬内的特性标注/徽标行，必须单独计算其 `y + height` 不超出层底衬的 `y + height - 8` |
| 4.10.4 | **自检脚本**（v1.2 新增）：写完 SVG 后运行 Python 检查——扫描所有 `<g transform="translate(X,Y)">` 内的 `<rect>` 和 `<text>`，找出任何 `text.y + fontSize > container.bottom` 的违规项 |
| 4.10.5 | **KPI 分隔线不得触碰容器底边（v1.3 新增）**：KPI 栏内分隔线 `y2` 必须 ≤ `栏高 - 4px`。禁止分隔线下端切齐栏底边界（视觉上产生溢出错觉） |

### 4.11 灰度色彩对比度禁令（2026-05-17 v1.3 新增）

**核心原则**：灰度色块（`#E5E7EB`、`#D1D5DB`、`#9CA3AF` 等）上面放中灰色文字（`#6b7280`、`#9ca3af`、`#4b5563`）时，背景与文字明度差过小，人眼无法快速分辨。**同一色系相邻明度色片不得形成「背景-文字」关系。**

| 规则 | 说明 |
|---|---|
| 4.11.1 | 灰底（`L ≥ 70%` 的灰度，如 `#E5E7EB`）上的文字必须用 **`#1a1a1a` 或 `#374151`**（明度差 ≥ 40%），禁止用 `#6b7280`/`#9ca3af` |
| 4.11.2 | 任何标签/徽标/特性标注的背景色若取自灰度色系（`#F3F4F6`、`#E5E7EB`、`#D1D5DB`），则文字必须为纯黑 `#1a1a1a` 或深色品牌色，确保对比度肉眼可见 |
| 4.11.3 | **自检**：写完 SVG 后肉眼检查每个灰色背景块上的文字，确认"一眼能读"。预览模式下眯眼看——如果文字融进了背景，就是违规 |

## 5 · 4 层架构图骨架模板

适用于：表达"用户 → Agent → 数据 → 规则"这种分层抽象。

```
viewBox: 1280 × {根据内容调高度}

┌─ 头部标题区（y=0-160）──────────────────────┐
│  · 主标题 (32px)                              │
│  · 副标题 (14px)                              │
│  · 状态条卡片（一行 KPI / 当前规模）          │
└──────────────────────────────────────────────┘

┌─ L0 用户/输入层（高 100）────────────────────┐
│ [80×100 紫] │  用户卡片（含头像 + 角色 + 标签）│
└──────────────────────────────────────────────┘
                ↓ 主箭头
┌─ L1 执行层（高 220）────────────────────────┐
│ [80×220 黑] │ 4 个 Agent 卡片（横排，270 宽） │
└──────────────────────────────────────────────┘
                ↓ 多条主箭头（每个 Agent 一条）
┌─ L2 数据/知识层（高 ≥400）──────────────────┐
│ [80×h teal] │ 主卡（780宽）+ 副卡（304宽）    │
│             │ 内部至少 3 个内容块，间距 22+    │
└──────────────────────────────────────────────┘
                ↑ 反馈/约束箭头
┌─ L3 规则层（高 120）────────────────────────┐
│ [80×120 灰] │ 3 个规则卡片（横排，356 宽）   │
└──────────────────────────────────────────────┘

┌─ 底部：图例 + 流程缩略 + KPI + 页脚 ─────────┐
└──────────────────────────────────────────────┘
```

### 关键尺寸

```
画布宽度: 1280
左边距: 40
右边距: 40
有效宽度: 1200

层标签: 80 宽 × 与卡片同高
卡片区起点 x: 100 (40 + 80 - 20，与层标签贴合)
卡片区宽度: 1100

L1 4 个 Agent 卡片: 265 宽 × 220 高，间距 14
L3 3 个规则卡片: 356 宽 × 120 高，间距 14
```

## 6 · 箭头规范

### 6.1 4 种箭头类型

```css
.arrow-main     { stroke: #1f2937; stroke-width: 2;   }                        /* 主数据流（实线粗） */
.arrow-feedback { stroke: #861B2F; stroke-width: 1.5; stroke-dasharray: 5,3; } /* 反馈/评审（红虚） */
.arrow-rule     { stroke: #4A5568; stroke-width: 1.5; stroke-dasharray: 2,3; } /* 规则约束（灰点虚） */
.arrow-data     { stroke: #2D9C4F; stroke-width: 1.5; }                        /* 资料流转（绿实细） */
```

### 6.2 箭头实现方式（重要：场景区分）

> **2026-05-26 修订**：`<marker>` 在内联 HTML SVG 中存在严重跨浏览器兼容问题（Chrome/Safari/Firefox 表现不一致，常见症状：红色方块、箭头偏移、箭头不显示）。必须按场景选择实现方式。

#### 场景 A：独立 .svg 文件（Obsidian 嵌入 `![[xxx.svg]]`）

可以使用 `<marker>`，但必须遵守以下约束：

```xml
<defs>
  <marker id="arr-main" viewBox="0 0 10 10" refX="9" refY="5"
          markerWidth="7" markerHeight="7" orient="auto">
    <path d="M 0 0 L 10 5 L 0 10 z" fill="#1f2937"/>
  </marker>
</defs>
```

- 每种颜色的箭头一个 marker（不能复用，因为 fill 颜色不同）
- marker ID 必须全局唯一（同一文档中多个 SVG 会共享 ID 命名空间）
- `<path>` 内必须显式 `fill="颜色"`，不能省略（省略 = 默认 fill black = 黑色三角）

#### 场景 B：内联 HTML SVG（嵌在 HTML 页面中）-- 禁止使用 marker

**铁律：HTML 页面内嵌 SVG 禁止使用 `<marker>`。** 改用手动 `<polygon>` 箭头。

原因：
1. 多个内联 SVG 共享同一 document，marker ID 必然冲突
2. 浏览器对 `marker-end` 的渲染时序不确定，页面加载时常出现红色方块/黑色方块
3. Safari 对 `refX/refY` 的解释与 Chrome 不同，箭头位置偏移

**正确方案——polygon 手动箭头：**

```xml
<!-- 向下箭头：终点 (x, y)，三角形尖端朝下 -->
<polygon points="x-4,y-7 x+4,y-7 x,y" fill="#颜色"/>

<!-- 向右箭头：终点 (x, y)，三角形尖端朝右 -->
<polygon points="x-7,y-4 x-7,y+4 x,y" fill="#颜色"/>

<!-- 向上箭头：终点 (x, y)，三角形尖端朝上 -->
<polygon points="x-4,y+7 x+4,y+7 x,y" fill="#颜色"/>

<!-- 向左箭头：终点 (x, y)，三角形尖端朝左 -->
<polygon points="x+7,y-4 x+7,y+4 x,y" fill="#颜色"/>
```

示例（从 (200,50) 向下到 (200,150) 的带箭头连线）：

```xml
<line x1="200" y1="50" x2="200" y2="150" stroke="#1f2937" stroke-width="2" fill="none"/>
<polygon points="196,143 204,143 200,150" fill="#1f2937"/>
```

#### 6.2.1 通用安全规则（两种场景都适用）

| 规则 | 说明 |
|------|------|
| 6.2.1a | 所有 `<path>` 用于连线时必须显式 `fill="none"`。省略 fill 会导致 path 围成的区域被填充为黑色实心形状 |
| 6.2.1b | 所有 `<line>` 元素必须使用 `x1/y1/x2/y2` 四属性，不能写 `x/y`（那是 `<rect>` 的属性） |
| 6.2.1c | 同一 HTML 文档中多个 SVG 的所有 ID 必须全局唯一（加前缀如 `svg1-arr`、`svg2-arr`） |
| 6.2.1d | 箭头颜色必须与连线 stroke 颜色一致 |
| 6.2.1e | polygon 箭头的三角形大小建议：短边 8px（±4）、长边 7px，与 stroke-width:2 的线条匹配 |

### 6.4 连线美观规则（2026-05-17 新增）

| 规则 | 说明 |
|---|---|
| 6.4.1 | **禁止硬直角折线**。所有多段连线使用 `path` 的贝塞尔曲线（`C`）或圆角路径（`arc`），转角半径 ≥ 6px |
| 6.4.2 | 连线经过卡片时**必须绕行**（路径中加入偏转点），禁止穿过卡片文字区 |
| 6.4.3 | 箭头终点必须精确落在卡片边缘，不得伸进卡片内部超过 3px |
| 6.4.4 | 多条平行连线间距 ≥ 10px，防止视觉粘连 |

`flow-label` (11px font-weight 600) 放在箭头侧边或上方，距离 4-8px。颜色与箭头同色。

## 7 · 卡片规范

### 7.1 卡片骨架

```xml
<g transform="translate(x,y)">
  <!-- 主背景 -->
  <rect width="W" height="H" rx="8" fill="#ffffff" stroke="{主色}" stroke-width="2"/>

  <!-- 顶部色条（高 36-40） -->
  <rect width="W" height="36" rx="8" fill="{主色}"/>
  <rect y="28" width="W" height="8" fill="{主色}"/> <!-- 这一行抹掉底部圆角 -->

  <!-- 标题区 -->
  <text x="14" y="24" font-size="20">{emoji}</text>
  <text class="card-title" fill="#fff" x="42" y="24">{标题}</text>
  <text class="badge" x="W-15" y="22" text-anchor="end">{右上徽标}</text>

  <!-- 内容区，相对偏移 14, 头部高 + 16 -->
  <g transform="translate(14, 52)">
    ...
  </g>
</g>
```

### 7.3 卡片重叠防止规则（2026-05-17 新增）

| 规则 | 说明 |
|---|---|
| 7.3.1 | 任何两张卡片之间**禁止重叠**（包括描边虚线框）。装饰性虚线框（选中/高亮/关联）必须完整包围目标卡片，不得被卡片背景遮挡 |
| 7.3.2 | 若需在卡片上叠加状态标签（如「不需要」「已废弃」），标签必须放在卡片**右上角外**或底部栏外，不得压在正文上 |
| 7.3.3 | 虚线框的 `stroke-dasharray` 必须均匀闭合（如 `stroke-dasharray="4,3"`），不得出现孤立的虚线片段（表示图层遮挡） |

### 7.4 中文字体渲染安全规则（2026-05-17 新增）

| 规则 | 说明 |
|---|---|
| 7.4.1 | SVG 中所有 `<text>` 必须声明 `xml:lang="zh-CN"`，辅助渲染引擎选择正确的字形 |
| 7.4.2 | 中文 `<text>` 元素不得使用 `letter-spacing` 属性——不同 OS 对中文字间距的处理不一致，会导致字形拆解 |
| 7.4.3 | 禁止将多个短 `<text>` 元素叠加在同一坐标来实现「排版」（如标题用一个 text、副标题用另一个 text 且 y 相同）。每行独立 y 坐标 |

## 8 · 必备元素清单

任何"总架构图"级别的 SVG 应包含：

- [ ] 主标题 + 副标题（说明这张图讲什么）
- [ ] 状态条 / 当前规模条（让读者一眼知道系统的"当前体量"）
- [ ] 分层标签（L0/L1/L2/L3 这种，让层次感强）
- [ ] 至少 1 种箭头 + marker 定义
- [ ] 图例（说明箭头颜色含义）
- [ ] KPI 卡片（关键指标数字，让读者带走"3-5 个能记住的数字"）
- [ ] 页脚（作者 / 评审 / 适用范围 / 关联文档 wikilink）

## 9 · 修改流程

```
改 SVG → 浏览器/Obsidian 渲染验证 → 防重叠检查清单 → 更新源文档版本号 → commit
```

**禁止**：
- 改 SVG 不改源文档（架构变了 markdown 没同步会误导）
- 用 PPT/Figma 导出 SVG 直接放进 vault（导出 SVG 包含大量 `<defs>` 噪音和绝对坐标，难维护）
- 同一张图存多个版本（改 v2 直接覆盖 v1，不要 `-final.svg` `-v2.svg`）

### 大版本变更

SVG 大改（如新增一层、重构骨架）按 vault "版本不覆盖" 规则：

```
原文件 → 移到 50-经验/_archive/{原名}-{日期}.svg
新文件 → 用同名（如 多智能体协作方法论-v5-架构图.svg）
源 markdown → 同步引用
```

## 10 · 反例（不要这样写）

### ❌ 反例 1：硬编码字体
```xml
<text style="font-family: 'Arial Black'">...</text>  <!-- 中文会回退到默认字体，丑 -->
```

### ❌ 反例 2：滥用 emoji 当图标
```xml
<text font-size="48">🚀🎉✨💫⭐</text>  <!-- 会议汇报场合显得不专业 -->
```

只在标题前后单个 emoji（如 `📦 Vault`），不要堆叠。

### ❌ 反例 3：没算清楚 y 就写
```xml
<g transform="translate(20, 60)">
  <rect height="100"/>
</g>
<g transform="translate(20, 100)">  <!-- 100 < 60+100=160，明显重叠 -->
  <text>下一块</text>
</g>
```

### ❌ 反例 4：颜色随意
```xml
<rect fill="red"/>           <!-- "red" 不是品牌色 -->
<rect fill="#FF0000"/>       <!-- 不在 token 里 -->
<rect fill="#861B2F"/>       <!-- ✅ 品牌色 token -->
```
