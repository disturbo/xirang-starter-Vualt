# Agent 事件流规范 v2.0

> `智能体事件.jsonl` 是 append-only 的事件日志。每个 Agent 在状态变更时追加一行 JSON。
> 与 per-agent 状态文件（当前态快照）互补：状态文件回答"现在是什么"，事件流回答"怎么到的这里"。
> v2.0：新增 §3 事件模板库（生成式），Agent 直接复制模板填空。

## 0 使用方式

**Agent 写事件时不需要通读全文**——直接跳到 §3 复制对应模板，填入变量即可。

```text
我要写什么事件？
 ├─ 开始任务？→ §3.1 task_start 模板
 ├─ 完成任务？→ §3.2 task_end 模板
 ├─ 遇到错误？→ §3.3 error 模板
 ├─ 长任务心跳？→ §3.4 heartbeat 模板
 ├─ spawn 子Agent？→ §3.5 spawn / spawn_end 模板
 ├─ 状态变更？→ §3.6 status_change 模板
 ├─ 成本告警？→ §3.7 cost_alert 模板
 └─ 升级通知？→ §3.8 escalation 模板
```

## 1. 设计目标

| 目标 | 实现方式 |
|------|---------|
| 审计追溯 | 每条事件含时间戳+agent+动作，可回溯任何时刻的系统状态 |
| 成本统计 | task_end 事件含 tokens/cost，周报可直接从 jsonl 汇总 |
| 故障诊断 | error 事件含错误码+上下文，WorkBuddy 可读取排障 |
| 低冲突 | append-only 追加写，多 Agent 同时写不会互相覆盖（文件锁保护） |
| 轻量 | 无需数据库，纯文本 jsonl，grep/jq 即可查询 |

## 2. 事件类型

| event | 触发时机 | 必填字段 | 可选字段 |
|-------|---------|---------|---------|
| `task_start` | Agent 开始任务 | ts, agent, task | task_id, model, budget_level |
| `task_end` | Agent 完成任务 | ts, agent, task, status | task_id, tokens, cost_cny, duration_sec |
| `error` | Agent 遇到异常 | ts, agent, task, error_code | error_msg, retry_count |
| `heartbeat` | 长任务心跳 | ts, agent, task, progress | pct, tokens_so_far |
| `spawn` | 父 Agent spawn 子 Agent | ts, agent, sub_id, task | model, timeout_sec |
| `spawn_end` | 子 Agent 完成/失败 | ts, agent, sub_id, status | tokens, error_code |
| `status_change` | Agent 状态变更 | ts, agent, from_status, to_status | reason |
| `cost_alert` | 成本告警触发 | ts, agent, alert_level | weekly_cost, ceiling |

## 4. JSON Schema（参考）

每行一个 JSON 对象（JSONL 格式），必填字段：

```json
{
  "ts": "2026-05-17T22:30:00+08:00",  // ISO 8601 时间戳
  "agent": "claudian",                  // agent_id（与状态文件一致）
  "event": "task_end",                  // 事件类型（见上表）
  "task": "S4 状态表 per-agent 拆分"     // 任务名
}
```

扩展字段按事件类型添加：

```json
// task_end 示例（含 task_id 关联 task card）
{"ts":"2026-05-17T22:00:00+08:00","agent":"claudian","event":"task_end","task":"S4 状态表 per-agent 拆分","task_id":"T-20260517-S4","status":"done","tokens":45000,"cost_cny":0.09,"duration_sec":1800}

// error 示例
{"ts":"2026-05-17T22:15:00+08:00","agent":"hongmeisu","event":"error","task":"代码实现","error_code":"E-TIMEOUT","error_msg":"子Agent超时300s无响应","retry_count":1}

// spawn 示例
{"ts":"2026-05-17T22:10:00+08:00","agent":"qingmeisu","event":"spawn","sub_id":"sub-01","task":"原型并行生成","model":"haiku","timeout_sec":300}

// cost_alert 示例
{"ts":"2026-05-17T23:00:00+08:00","agent":"system","event":"cost_alert","alert_level":"L1","weekly_cost":165.0,"ceiling":200.0}
```

## 5. 写入规则

### 5.1 谁写

- 每个 Agent 写自己的事件（agent 字段 = 自己的 agent_id）
- WorkBuddy 可写 error 相关事件（代为记录崩溃 Agent 的 error）
- Claudian cron 可写 cost_alert 事件

### 5.2 何时写

| 时机 | 写什么 |
|------|--------|
| 任务开始（status→busy） | `task_start` |
| 任务结束（status→idle） | `task_end`（含 tokens/cost） |
| 任务失败（status→error） | `error` |
| 长任务中间（>120s） | `heartbeat`（与 heartbeat.json 同步） |
| spawn 子 Agent | `spawn` |
| 子 Agent 返回 | `spawn_end` |
| 状态变更 | `status_change` |
| 成本达阈值 | `cost_alert` |

### 5.3 写入方式

```bash
# Shell 追加（推荐，原子操作）
echo '{"ts":"'$(date -u +%Y-%m-%dT%H:%M:%S+08:00)'","agent":"claudian","event":"task_start","task":"任务名"}' >> 02-项目管理/智能体状态/智能体事件.jsonl

# Python 追加
import json, datetime
event = {"ts": datetime.datetime.now().isoformat(), "agent": "claudian", "event": "task_start", "task": "任务名"}
with open("02-项目管理/智能体状态/智能体事件.jsonl", "a") as f:
    f.write(json.dumps(event, ensure_ascii=False) + "\n")
```

### 5.4 并发安全

- JSONL append-only + 行级原子写入（单行 < 4KB，POSIX 保证原子）
- 极端并发（>3 Agent 同时写）：加文件锁 `flock`
- 不用担心读写冲突：读者读到的是某一瞬间的完整行集合

## 6. 查询方式

```bash
# 查某 Agent 本周所有事件
jq 'select(.agent == "claudian")' 智能体事件.jsonl

# 查所有 error 事件
jq 'select(.event == "error")' 智能体事件.jsonl

# 统计本周总成本
jq 'select(.event == "task_end") | .cost_cny // 0' 智能体事件.jsonl | paste -sd+ | bc

# 统计某 Agent 任务数
grep '"agent":"qingmeisu"' 智能体事件.jsonl | grep '"task_end"' | wc -l

# 按 task_id 聚合某任务的总成本（含 spawn 子任务）
jq 'select(.task_id == "T-20260518-05") | .cost_cny // 0' 智能体事件.jsonl | paste -sd+ | bc

# 重建某时刻的 Agent 状态（从事件流恢复）
jq 'select(.agent == "claudian" and .event == "status_change") | {ts, from: .from_status, to: .to_status}' 智能体事件.jsonl
```

## 7. 轮转策略

| 规则 | 说明 |

| 单文件上限 | 10MB 或 30 天（先到先轮转） |
| 轮转方式 | mv 智能体事件.jsonl → agent-events-{date}.jsonl.gz |
| 保留期 | 压缩文件保留 90 天 |

## 8. 与现有组件的关系

```
per-agent 状态文件（当前快照）     ←→    Dataview DQL 聚合视图
         ↑ 同步更新                          ↑ 实时查询
         │                                   │
Agent 执行任务 ──→ 智能体事件.jsonl ──→ 周成本报告
                   （历史审计日志）         （jq 汇总）
```

- **状态文件**：回答"每个 Agent 现在什么状态"（Dataview 可视化）
- **事件流**：回答"过去发生了什么"（审计 + 统计 + 故障回溯）
- **两者互补不替代**：状态文件是快照（O(1) 查当前），事件流是日志（O(n) 遍历历史）
