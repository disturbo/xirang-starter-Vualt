# V9.4.3 迭代记录

V9.4.3 是 V9.4 自证阶段的收束版本：它不改变“写文件才声明”的二元触发器，而是把 V9.4.0~V9.4.2 中形成的自证、状态机、分发扫描和成本口径统一进 starter 骨架。

## 核心变化

| 能力 | 说明 |
|---|---|
| starter strict 复扫 | 分发前用 `v9-starter-leak-check.py --strict` 扫个人路径、项目词、秘钥形态和运行态产物 |
| harness 回归测试 | `v9-harness-eval-runner.py` 用 positive/negative fixture 证明工具会拒绝已知坏样本 |
| self-accept 硬门禁 | `v9_accept` + `gate-enforce pre-accept` 防止 Agent 自行把自己的产物标成 accepted |
| Handoff 状态机 | `v9-handoff-check.py` 检查显式交接任务是否含产物、验证、next action |
| review 状态机补强 | `v9-task-state-check.py` 约束 submitted/accepted/changes_requested 的机器可读字段 |
| usage token 成本闭环 | `agent-cost-events.py` 支持 input/output tokens、usage_source、billing_status、cost_source |
| 八源反射器 | `v9-reflex-check.py` 汇总 project-ops、agent-state、heartbeat、policy、starter、task-state、scope、handoff |

## 仍未包含

- 不包含任何真实项目资料、客户资料、个人路径或账号秘钥。
- 不包含巡检快照、成本事件流、Agent 事件流等运行期产物。
- 不包含真实平台 CNY 账单接入；无 `billing_status=connected` + 平台 `cost_source` 时，`cost_cny` 不得当作账单金额。

## 验证建议

```bash
python3 02-项目管理/脚本/v9-harness-eval-runner.py
python3 02-项目管理/脚本/v9-starter-leak-check.py --root . --strict
python3 02-项目管理/脚本/v9-reflex-check.py --quiet
```

健康口径：`health-latest.json` 中 `sources_failed=[]` 且 `summary.active=0` 才是真静默。
