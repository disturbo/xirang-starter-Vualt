# V9.3.0 迭代记录

> 关键词：第一反射器、常驻巡检、自省字段、规范冲突扫描、真实计费未接入标注。

## 版本定位

V9.3.0 不改变 V9 的二元触发器，也不新增新的协作层。它补上的是反馈链中的评估环节：系统不只在写入前用 Gate/Hook 拦截，还会在写入后持续巡检任务、状态、心跳和规范冲突。

## 核心变化

| 变化 | 说明 |
|---|---|
| 第一反射器入编 | `v9-reflex-check.py` 聚合多个巡检源，统一输出 `health-latest.json` |
| 常驻巡检 | 支持 launchd 定时运行；自动化只写 `02-项目管理/巡检/`，不直接写看板/日志 |
| 自省字段 | `sources_run/sources_ok/sources_failed` 区分“跑了且干净”和“没跑/崩了” |
| 规范冲突扫描 | `v9-policy-conflict-check.py` 依据规范管辖权索引检查 primary/supporting/inactive 关系 |
| 成本口径标注 | 成本周报输出 `billing_status=not_connected`，真实计费接入前不把 CNY 当账单 |

## 健康判定

会话启动时读取 `02-项目管理/巡检/health-latest.json`：

| 条件 | 结论 |
|---|---|
| `summary.active=0` 且 `sources_failed=[]` | 真静默：四源都看过，且没有新增待上报项 |
| `summary.active=0` 但 `sources_failed` 非空 | 假静默：不是没事，而是巡检没看全 |
| `summary.active>0` 且含 p0/p1 | 需要人工确认后提升到看板或指派 owner |

## 兼容性

- 对 V9.2.x 任务卡、Gate、Hook、prompt-build 保持兼容。
- 第一反射器默认只写巡检目录，不污染正式看板。
- Starter Vault 不默认安装 launchd；需要常驻时按 `02-项目管理/巡检/README.md` 的模板自行启用。
