# V9.4 自证阶段 Charter

> 一句话目标：让 V9 能测试自己的工具、约束自己的状态、保护自己的分发边界。先自证，再谈更重的 AgentOps 与真实计费。

## 背景判断

最近暴露的真实问题不是“账不准”，而是 harness 自身不可信：

| 事故 | 暴露的问题 |
|---|---|
| `v8_handshake` zsh bug | 工具脚本错误，但系统没有回归测试发现 |
| `v8-health-metrics.py` 读错目录 | 健康指标假绿，实际没测准 |
| starter 公开分发 | 项目私货泄漏风险已变成 live 风险 |
| `submitted != accepted` 靠纪律 | 验收边界没有机器可读状态机强制 |

所以 V9.4 起步不把真实计费作为主线。V9.4.3 已补 usage token 最小闭环，但真实 CNY 账单仍需平台成本来源；无 `billing_status=connected` + `cost_source` 时，不得把 `cost_cny` 当账单。

## 阶段原则

| 原则 | 解释 |
|---|---|
| 绿灯无感 | 无异常、无高风险边界时，不给普通任务加税 |
| 红灯硬拦 | 触及验收、权限、分发、秘钥、常驻部署时强制停住 |
| 先坏样本，后好样本 | eval-runner 必须证明能拒绝 known-bad fixture，避免假绿 |
| 只做机械 eval | 第一轮只测可确定断言，不做 LLM 质量评分 |
| 自演进不自放权 | Agent 可提案改规则，不可自行把约束改松 |

## 非目标

| 非目标 | 原因 |
|---|---|
| 完整 LLM-judge 评分 | 贵、不稳定，第一轮不能作为硬门禁 |
| 多平台真实账单统一 | 外部 API 依赖重；危险口径已由 `billing_status` 拆掉 |
| 完整 MCP/tool registry | 等回归测试和状态机先稳定 |
| A2A 生产化 | 当前单机工作流够用 |

## #2 Harness 回归测试的硬约束

eval-runner 不能只跑 known-good。必须先证明能拒绝 known-bad：

| negative fixture | 必须失败的断言 |
|---|---|
| 缺字段任务卡 | `project-ops-check.py --json` 必须产生 p1 |
| 越权写入 scope | gate 必须拒绝 |
| `reviewer == author` 的 accept | `pre-accept` 必须拒绝 |
| 缺 handoff closeout | closeout check 必须拒绝 |
| 损坏 JSON 输出源 | 反射器必须标记 `SOURCE_FAILED` 或 `SOURCE_CRASHED` |

验收标准：报告里必须明确区分 `passed_positive` 与 `blocked_negative`。如果只显示 “N/N pass”，不得上线。

## #3 状态机硬化的数据模型前置

任务卡 frontmatter 需要补足机器可读验收字段：

| 字段 | 用途 |
|---|---|
| `owner` / `author` | 执行者或产物作者 |
| `reviewer` | 指定验收方 |
| `accepted_by` | 实际确认 accepted 的人或 Agent |
| `accepted_at` | accepted 时间 |
| `acceptance_result` | `accepted / rejected / changes_requested` |

硬规则：

1. `accepted_by` 不得等于 `owner` / `author`。
2. Agent 不得自行把自己产物从 `submitted` 推到 `accepted`。
3. 手改自身 write_scope 属于权限放宽，必须进入 HITL 拍板路径。

## #4 starter 泄漏扫描边界

最小实现只做只读扫描，不自动改 starter：

- 默认扫描 `XIRANG_STARTER_ROOT`；未设置时扫描当前 Vault 的兄弟目录 `../xi-rang-v9-starter`。
- 命中个人路径、项目品牌、车型代号、旧 agent id、真实 token 模式时产出 p1。
- 缺少 starter 根目录时产出 advisory，不阻断主 Vault 运行。
- 结果进入 `health-latest.json` 的第五源 `starter-leak`。

## 退出标准

V9.4 第一批完成的最低标准：

1. HITL 清单已落文档，后续规则可引用。
2. starter 泄漏扫描接入反射器，`sources_run` 能看到 `starter-leak=ok(...)`。
3. eval-runner 可手动运行并由 pre-commit/验收新鲜度触发，且报告明确区分 `passed_positive` / `blocked_negative`。
4. 新机制在无异常时只写巡检 JSON，不主动污染看板/日志。
5. `task-state` 与 `handoff` 进入 `sources_run`，但不阻断普通任务收工；只在 accepted 转移和显式 handoff 收工态硬拦。
