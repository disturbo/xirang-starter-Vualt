# 息壤 V9 部署指南

> 核心理念：**部署不是复制环境，是和使用者逐步对齐工作方式。**
> 不是每个人都要达到息壤完全体。完全体是给系统管理员准备的，不是给用户准备的。
> 设计方法论参考 [[Claude Design 方法论研究]]。环境详细依赖见 [[息壤V9-环境还原清单]]。

### 跨平台约定

本指南同时覆盖 **Mac** 和 **Windows**。阅读时只看自己平台的部分即可。

| 约定 | Mac | Windows |
|------|-----|---------|
| 终端 | Terminal（自带） | PowerShell（自带，右键开始菜单打开） |
| 包管理器 | `brew`（Homebrew） | `winget`（自带）或 `scoop` |
| 快捷键前缀 | Cmd | Ctrl |
| 用户目录 | `~/` | `C:\Users\你的用户名\` |
| 默认 Vault 路径 | `~/Desktop/obsidianVault/` | `C:\Users\你的用户名\Desktop\obsidianVault\` |
| 环境变量配置 | 写入 `~/.zshrc` | 写入 PowerShell `$PROFILE` 或系统环境变量 |
| 定时任务 | `crontab` | 任务计划程序（Task Scheduler） |

> 代码块中用 `# Mac` / `# Windows` 标注。看到不是你平台的行，跳过就好。

## 1. 引导者须知

**本文件的读者是你——部署引导者（管理员/负责人）。** 不是被部署者本人。

你的工作流：
1. 和对方聊 5 分钟（Phase 1-2），确定他是 L0/L1/L2/L3
2. 翻到对应阶段的"完整操作步骤"，当面或远程带他装完
3. 装完后把"日常使用速查卡"发给他（每个阶段有一张）

你需要提前准备：
- 确认对方的操作系统（Mac / Windows）
- Vault 的分发方式（AirDrop/U盘/网盘 zip/Git clone）
- 各阶段可能需要的 API Key 申请链接
- 本文件 + [[息壤V9-环境还原清单]]（详细版本号和工具列表）

V9 相比 V8 的部署简化：
- L2 用户不再需要理解 M0-M5 六档，只需知道「写文件要声明，不写直接做」
- L3 用户的合规配置由 `prompt-build.py` 自动分发，不再手工复制
- `gate-enforce.py` 自动拦截违规写入，减少人工自检负担

## 2. 息壤四阶段 — 先定"到此为止"的线

> 部署之前，先回答一个问题：**这个人该停在哪？**

### 判断标准

> 他的日常工作中，有没有"重复产出结构化交付物"的场景？

- 没有 → L0 或 L1 足够
- 有（写 PRD、出方案、做评审）→ L2 有价值
- 需要多个 AI 角色配合跑完整流程 → L3，但通常团队只有 1-2 人需要

### 四阶段总览

```
L0 浏览者        L1 问答者        L2 产出者        L3 协作者
"看文档就行"     "偶尔问 AI"     "AI 帮我出活"    "多 AI 跑流程"
   |               |               |               |
 Obsidian        + Claude Code    + 角色设定       + 多 Agent
 看 PRD            或 OpenClaw     + 二元触发器     + 看板状态机
 看板留言          项目背景贴上去    + 质量自检       + 事件流审计
                                   + 产出归档       + 自动编排
   |               |               |               |
 2 分钟           10 分钟          20 分钟          1 小时
 0 元             按量付费          按量付费         多个 API Key
```

### 角色 → 阶段映射

| 角色 | 推荐阶段 | 理由 | 该阶段的"最小动作" |
|------|:---:|------|------|
| 管理者/总监 | L0-L1 | 看文档、做决策 | 装 Obsidian，打开 Vault 浏览 |
| 项目经理 | L1 | 看进度、派活、偶尔问 AI | 把项目背景写成一段话，贴给 AI |
| 产品经理 | L2 | 重复产出 PRD/方案 | 用角色设定 + 模板写一次 PRD |
| 方案/交付 | L2 | 写方案、做评审 | 选一个重复任务，跑一次完整流程 |
| 前端开发 | L2-L3 | 跑原型、代码生成 | 从息壤工具中选一个用一周 |
| 基建/架构 | L3 | 维护整套协作环境 | 完整部署，唯一需要完全体的角色 |

> **工具箱，不是考试大纲。只做一件，试一周，好用再加第二件。**

## 3. 总览：3 Phase x 10 Step

> 源自 Claude Design 方法论的"渐进收敛"理念：不是一步到位，是逐步对齐。

```
Phase 1：构建个人工作画像（了解你是谁）
  Step 1  部署前收集表（all optional）
  Step 2  分析等待 — 生成个人画像 + 推荐阶段
  Step 3  画像 Review（对话式调整）
       |
Phase 2：需求收敛 → 方案对齐（确认你需要什么）
  Step 4  动态需求问卷（按推荐阶段生成不同问题）
  Step 5  参考系对标（"类似 xxx 的使用方式"）
  Step 6  方案确认（L0 / L1 / L2 / L3 四档选一）
       |
Phase 3：部署执行 → 验证（把东西装好）
  Step 7  结构确认稿（装什么 + 不装什么）
  Step 8  生成个性化部署脚本
  Step 9  执行部署 + 逐步验证
  Step 10 参数化调优 + 升级路径

贯穿全流程：
  · 每一步对用户可见（todo 透明）
  · 任何一步都可以回退重来
  · 最终产物是"你理解的环境"，不是"别人的环境拷贝"
```

## 4. L0 浏览者 · 完整操作（2 分钟）

### 前置条件

- Mac 或 Windows 电脑
- 能联网（下载 Obsidian）

### 操作步骤

**Step 1：安装 Obsidian**

```bash
# Mac
brew install --cask obsidian
# 或直接下载：https://obsidian.md/download → DMG → 拖到 Applications

# Windows
winget install Obsidian.Obsidian
# 或直接下载：https://obsidian.md/download → exe 安装包 → 双击安装
```

**Step 2：获取 Vault**

- U盘/网盘 zip（推荐，最快）
- Mac 还可以用 AirDrop
- Git clone（需 GitHub 账号）→ `git clone <repo-url>`

放到哪里：

| 平台 | 路径 |
|------|------|
| Mac | `~/Desktop/obsidianVault/` |
| Windows | `C:\Users\你的用户名\Desktop\obsidianVault\` |

**Step 3：打开 Vault**

1. 启动 Obsidian → "打开文件夹作为仓库"（Open folder as vault）→ 选择上面的 Vault 目录
2. 等待 30 秒索引加载
3. 按 `Cmd/Ctrl + O` 搜索「Home」→ 打开 `00-MOC/Home.md`

### 验证清单

```
[ ] Obsidian 能启动
[ ] Vault 能打开，左侧文件树有内容
[ ] Cmd/Ctrl + O 能搜索到文件
[ ] 打开 00-MOC/多智能体协作看板.md 能正常显示
```

### L0 日常使用速查卡

```
日常操作（Mac 用 Cmd，Windows 用 Ctrl）：
  Cmd/Ctrl + O           搜索文件
  Cmd/Ctrl + Shift + F   全文搜索
  Cmd/Ctrl + P           命令面板

看文档：
  从 00-MOC/Home.md 开始浏览

给 AI 派活：
  打开 00-MOC/多智能体协作看板.md → 跨智能体消息区 → 按模板写
```

## 5. L1 问答者 · 完整操作（10 分钟）

### 前置条件

- L0 已完成
- 对方愿意用终端（Mac Terminal / Windows PowerShell，哪怕只学一条命令）

### 操作步骤

**Step 1：安装基础环境**

```bash
# Mac —— 先装 Homebrew（如果没有），再装 Node.js
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install node@22

# Windows —— 打开 PowerShell，直接装 Node.js
winget install OpenJS.NodeJS.LTS
# 装完后关闭并重新打开 PowerShell，让 PATH 生效
```

验证（两个平台命令一样）：
```bash
node --version   # 应显示 v22.x
```

**Step 2：安装 AI 对话工具**

npm 命令在 Mac 和 Windows 上完全一样，根据对方偏好选一个：

```bash
# 方式 A：Claude Code（推荐，直接在终端对话）
npm install -g @anthropic-ai/claude-code
claude --version

# 方式 B：OpenClaw（TUI 界面，支持国内模型）
npm install -g openclaw
openclaw --version
```

**Step 3：配置 API Key**

Claude Code 方式（两个平台一样）：
```bash
claude login
# 按提示完成认证
```

OpenClaw + DeepSeek 方式（两个平台一样）：
```bash
openclaw configure
# 选择 "Add custom provider" → deepseek
# Base URL: https://api.deepseek.com/v1
# API Key: sk-xxx（从 platform.deepseek.com 申请）
# 模型: deepseek-chat
```

**Step 4：创建最小项目记忆**

最简单的方式：用 Obsidian 直接在 Vault 根目录新建 `project-context.md`，粘贴以下内容：

```markdown
# 项目背景

## 我是谁
- 姓名：[填]
- 角色：[填]
- 负责项目：[填]

## 项目概况
- 项目名称：[填]
- 当前阶段：[填]

## 关键决策记录
（每次和 AI 聊完重要结论，追加到这里）
```

> 也可以用命令行创建。Mac 用 `cat > project-context.md << 'EOF' ... EOF`，Windows 用 Obsidian 新建更简单。

**Step 5：验证**

```bash
# Claude Code（两个平台一样）
claude "你好，请简单介绍你自己"

# 或 OpenClaw
openclaw terminal
# 在 TUI 里提问
```

### 验证清单

```
[ ] node --version 有输出
[ ] AI 工具已安装并能正常对话
[ ] project-context.md 已创建并填了内容
```

### L1 日常使用速查卡

```
问 AI：
  claude "你的问题"            # Claude Code 一次性提问
  openclaw terminal           # OpenClaw TUI 对话

更新项目记忆：
  用 Obsidian 打开 project-context.md
  追加到「关键决策记录」区

其他同 L0：
  Cmd/Ctrl + O 搜索 / 看板派活
```

## 6. L2 产出者 · 完整操作（20 分钟）

### 前置条件

- L1 已完成
- 对方有明确的重复产出需求（如每周写 PRD）

### V9 要点（L2 需要理解的合规最小集）

> L2 用户只需记住一条规则：
> **写文件前要声明，不写文件直接做。**
>
> 不需要理解 M0-M5 档位判定、不需要管看板状态机、不需要碰 `.standards/` 脚本。

### 操作步骤

**Step 1-5：同 L1**（如果从零开始，先完成 L1）

**Step 6：配置角色设定**

用 Obsidian 打开 Vault 中的 `.claude/CLAUDE.md`（如果没有就新建），写入以下内容：

```markdown
# 项目指令

## 身份
你是一位企业系统产品顾问。

## 产出规则
- PRD 包含：背景、目标、范围、用户故事、流程、字段表、验收标准
- 不确定的内容标注「待确认」
- 输出中文，格式用 Markdown
- 先列骨架大纲，确认后再展开细节

## 合规（V9 二元触发器）
写文件前要声明：V9 写入声明：{路径} | {动作摘要}
不写文件直接回复，无合规开销。
```

> `.claude/` 是隐藏文件夹。Mac 在 Finder 中按 `Cmd + Shift + .` 显示隐藏文件；Windows 在资源管理器「查看」→ 勾选「隐藏的项目」。
> 用 Obsidian 操作更简单：`Cmd/Ctrl + O` 搜索 `CLAUDE` 即可找到。
> 注意：L3 管理员的 CLAUDE.md 比这复杂得多。L2 用户只需要这个最小版本。

**Step 7：确认产出模板**

在 Obsidian 中打开 `30-规范/` 文件夹，确认里面有 PRD输出规范、原型输出规范等模板文件。

**Step 8：验证完整工作流**

在终端中执行（Mac 和 Windows 命令一样）：

```bash
claude "参考 30-规范/PRD输出规范-通用版-v1.0.md 的格式，帮我写一份「服务预约列表」模块的 PRD 骨架。只列大纲，不展开细节。"
```

检查输出：
- 有没有按规范结构来？
- 角色设定生效了吗？
- 不确定的地方有没有标「待确认」？

**Step 9：教会分步产出法（5 分钟口头讲解）**

告诉对方：

> "不要一次性让 AI 把整个 PRD 写完。分三步：
> 1. 先让它列骨架大纲（2 分钟看完确认）
> 2. 骨架 OK 后，逐章让它展开
> 3. 全部写完后对照规范检查清单自查
>
> 这样即使某一步不对，你知道是哪步出的问题。"

### 验证清单

```
[ ] L1 全部验证通过
[ ] .claude/CLAUDE.md 配好（角色设定 + V9 最小合规）
[ ] 30-规范/ 下的模板文件存在
[ ] 提问输出符合 PRD 规范格式
[ ] 对方理解"先骨架再展开"的分步产出法
[ ] 对方理解"写文件要声明"的 V9 规则
```

### L2 日常使用速查卡

```
写 PRD / 方案（分步法）：

  第 1 步 · 出骨架：
    claude "参考 PRD输出规范，帮我写 [模块名] 的 PRD 骨架，只列章节大纲"

  第 2 步 · 逐章展开：
    claude "展开第 4 章'流程'，包含主流程和异常流程"

  第 3 步 · 自查：
    对照 30-规范/ 里的检查清单

  写文件前记得声明：
    "V9 写入声明：10-项目/XX/PRD.md | 写 PRD 初稿"

产出物放哪：
  10-项目/项目名/ 下

其他同 L0/L1：
  Cmd/Ctrl + O 搜索 / 看板派活
```

### L2 不需要碰的东西

```
明确排除（这些是 L3 管理员的事）：
- 看板调度、Agent 状态文件、事件流
- 完整 pre-flight 握手流程、收工三件套
- GBrain、Ollama、多 Agent 编排
- .standards/ 下的任何脚本
- prompt-build 分发系统
- gate-enforce 门禁
```

## 7. L3 协作者 · 完整操作（1 小时）

### 前置条件

- L2 已完成
- 对方有终端操作能力
- 已确认需要多 Agent 协作能力
- 通常只有团队中 1-2 人需要

### Windows 用户必读

L3 依赖多个 Shell 脚本（`.sh` 文件）和 `crontab` 定时任务，这些在 Windows 上无法直接运行。
**推荐方案：安装 WSL2**（Windows Subsystem for Linux），之后所有命令都按 Mac/Linux 方式操作。

```powershell
# 在 PowerShell（管理员）中执行，装完需重启电脑
wsl --install

# 重启后打开 "Ubuntu"，设置用户名和密码
# 后续所有 L3 步骤在 Ubuntu 终端中执行即可
```

> WSL2 可以直接访问 Windows 文件系统，Vault 路径变为 `/mnt/c/Users/你的用户名/Desktop/obsidianVault/`。
> 安装 WSL2 后，L3 的所有步骤和 Mac 完全一致，无需额外适配。

### V9 完整合规体系

L3 用户需要理解完整的 V9 合规框架：
- **二元触发器**：写文件 → 声明 + pre-flight；不写 → 直接回复
- **三档声明**：M3（轻量）/ M4（完整）/ M5（跨 Agent）
- **Gate 强制**：gate-enforce.py 自动拦截违规（P0 硬阻断）
- **prompt-build 分发**：合规内容从单源分发到 7 个 Agent 平台
- **事件流审计**：所有生命周期事件 append-only 记录

### 操作步骤

> 详细版本号和工具路径见 [[息壤V9-环境还原清单]]。

**Step 1：安装系统基础**

> Windows 用户：如果已装 WSL2，以下命令在 Ubuntu 终端中执行。把 `brew` 替换为 `apt`（见下方）。

```bash
# Mac
brew install python@3.14
brew install ollama
brew install oven-sh/bun/bun  # 可选

# Windows (WSL2 Ubuntu)
sudo apt update && sudo apt install -y python3 python3-pip
curl -fsSL https://ollama.com/install.sh | sh
curl -fsSL https://bun.sh/install | bash  # 可选

# 两个平台都一样
ollama serve &
ollama pull bge-m3:latest
python3 --version  # >= 3.9（推荐 3.14）
```

**Step 2：安装全部 Agent CLI**

```bash
npm install -g @anthropic-ai/claude-code  # Claude Code
npm install -g openclaw                    # OpenClaw
npm install -g gbrain                      # GBrain 语义索引
npm install -g @openai/codex              # Codex（可选）
pip install hermes-ai                      # Hermes
```

**Step 3：配置全部 API Key**

```bash
# Claude Code（两个平台一样）
claude login

# OpenClaw 配置（两个平台一样）
openclaw configure
```

环境变量配置（按平台选一种）：

```bash
# Mac / WSL2 —— 写入 shell 配置
echo 'export ANTHROPIC_API_KEY="sk-ant-xxx"' >> ~/.zshrc
echo 'export OPENAI_API_KEY="sk-xxx"' >> ~/.zshrc
source ~/.zshrc
```

```powershell
# Windows 原生 PowerShell —— 写入系统环境变量
[System.Environment]::SetEnvironmentVariable("ANTHROPIC_API_KEY", "sk-ant-xxx", "User")
[System.Environment]::SetEnvironmentVariable("OPENAI_API_KEY", "sk-xxx", "User")
# 重新打开 PowerShell 生效
```

**Step 4：初始化 GBrain 语义索引**

```bash
gbrain init --repo ~/Desktop/obsidianVault
gbrain source add --name wiki --path ~/wiki/  # 可选
gbrain dream --repo ~/Desktop/obsidianVault   # 首次全量（几分钟）
gbrain status  # 验证
```

**Step 5：确认 Vault 基建完整**

> 以下命令 Mac 和 WSL2 通用。Windows 用户在 WSL2 Ubuntu 中执行，路径改为 `/mnt/c/Users/你的用户名/Desktop/obsidianVault`。

```bash
# .standards/ 脚本（32 文件）
ls $VAULT_ROOT/.standards/ | wc -l

# prompt-build 系统
ls $VAULT_ROOT/.prompt-src/

# Agent 状态文件
ls $VAULT_ROOT/02-项目管理/智能体状态/*.md

# Hooks 可执行
chmod +x $VAULT_ROOT/.standards/hooks/*.sh
```

**Step 6：配置外部平台**

```bash
# Hermes
# ~/.hermes/SOUL.md 内含 V9 合规块
# 由 prompt-build --apply-block 更新

# OpenClaw
# ~/.openclaw/workspace/AGENTS.md 内含 V9 合规块
# 技能包: ~/.openclaw/workspace/skills/v8-runtime/
```

**Step 7：配置定时任务**

Mac / WSL2（crontab）：

```bash
crontab -e
# 添加:
# GBrain 全量维护（6 小时）
0 */6 * * * ~/.npm-global/bin/gbrain dream --repo ~/Desktop/obsidianVault >> /tmp/gbrain-dream.log 2>&1
# GBrain 增量同步（30 分钟）
```

## 10. 设计原则

### 原则 1：信息收集方式匹配场景

| 场景 | 方式 | 用在哪 |
|------|------|--------|
| 已知结构，维度固定 | 表单 | Step 1 基本信息收集 |
| 未知偏好，因人而异 | 按阶段动态问卷 | Step 4 需求问卷 |
| 模糊需求，需要发掘 | 对话 | Step 3 画像调整 |
| 使用方式偏好 | 参考系对标 | Step 5 坐标映射 |

> 源自 Claude Design：表单是"已知信息结构"的最高效收集方式；对话是"未知信息发掘"的最高效收集方式。

### 原则 2：阶段切换时重新生成计划

Phase 1-2（了解+对齐）完成后，Phase 3（部署执行）重新生成全新计划。L0 是 3 步，L3 是 10 步——不是一个 10 步脚本删到 3 步。

### 原则 3：排除清单和安装清单同样重要

明确说"不装什么、不用什么"比默默不装更让人安心。尤其是 V9 合规部分——明确告诉 L2 用户"gate-enforce、prompt-build、事件流不是你要管的事"。

### 原则 4：升级是自然发生的，不是被推的

> "只做一件。试一周。好用再加第二件。"

每个阶段都应该能独立运行、独立产生价值。L0 浏览者打开 Vault 看到 PRD，这已经是价值了。

### 原则 5：过程确认的真正价值

当环境出问题时，用户能清晰定位问题在哪一层：是画像不准（回 Step 3）、阶段选错了（回 Step 6）、还是安装出错（回 Step 9）。
