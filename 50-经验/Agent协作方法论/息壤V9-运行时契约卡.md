# 息壤 V9 运行时契约卡

> Agent 唯一加载物。所有规则浓缩于此，不需要记忆更多。

---

## 铁律 1：二元触发器

```
收到消息 → 「这个任务会写文件吗？」
  不写 → 直接回复（零合规开销）
  写   → pre-flight（声明 → 亮灯 → 执行）
```

没有第三种情况。

---

## 铁律 2：唯一违规定义

> **写了文件但没声明 = 违规。**

---

## 铁律 3：写入声明格式

| 场景 | 格式 |
|------|------|
| M3（单文件，<20min） | `V9 写入声明：{路径} \| {动作摘要}` |
| M4（多文件/交付物） | 完整 `V9 已激活：` 块 |
| M5（跨Agent/长任务） | M4 + 预算 + 拆分计划 |

---

## 铁律 4：豁免清单

以下操作免声明：
- 追加运行日志一行（M3 收工）
- heartbeat 更新（状态文件 last_heartbeat 字段）

其他任何文件写入都需声明。

---

## 铁律 5：灰区处理

| 信号 | 判定 |
|------|------|
| 有具体对象 + 明确产出物 | 写文件 → pre-flight |
| 咨询语气（"怎么推进"/"能不能做"）| 不写文件 → 直接回复 |
| 无法判定 | 问用户确认，1 轮内决定 |

---

## 铁律 6：不写文件的场景

1. 解释概念 / 纯问答
2. 讨论方案（未到执行）
3. 评审 / 核对但不落盘
4. 日常闲聊
5. 巡检无异常 / 状态查询

巡检状态查询只读 `02-项目管理/巡检/health-latest.json`。健康判定必须同时满足 `summary.active=0` 与 `sources_failed=[]`；若 `sources_failed` 非空，即使没有 active 告警，也视为巡检源未看全。当前反射器为八源：project-ops / agent-state / heartbeat / policy-conflict / starter-leak / task-state / scope-tamper / handoff。

---

## 铁律 7：执行中扩展

执行中发现要写更多文件 → 暂停、补充声明、再继续。
每次写入前自问：「我声明过要写这个文件吗？」

---

## 铁律 8：闲聊不是任务

闲聊不需要建卡，不需要声明，不需要收工。
`submitted` 不等于 `accepted`：未经验收方确认，不得声称"已验收"。

验收任务卡必须走 `v9_accept <task_id> <accepted_by>` 或同等候选校验路径；Agent 不得裸改 `review_status: accepted`，`accepted_by` 不得等于 `owner/author`。

M5 或显式 `handoff_required: true` 的 done 任务，必须有可接手 Handoff：status、产物、验证结果、next action。

2026-06-27 起的新任务卡，`review_status=submitted/reviewing/changes_requested/rejected/accepted` 必须写 `submitted_at`。`changes_requested` 必须写 `acceptance_note`，否则接手方无法行动。

---

## 铁律 9：starter 与成本口径

对外 starter 发布前必须跑：

```bash
python3 02-项目管理/脚本/v9-starter-leak-check.py --root <starter> --json --strict
```

成本事件可以记录真实 usage token；但 `billing_status=connected` 必须有平台 `cost_source`。没有平台成本来源时，`cost_cny` 只能是估算/自报，不得当账单。

Harness / gate / 巡检脚本改动后必须跑 `v9-harness-eval-runner.py`；看 `blocked_negative`，不能只看总通过数。
