# 息壤 V9 运行时契约卡

> Agent 唯一加载物。所有规则浓缩于此，不需要记忆更多。

---

## 铁律 1：二元触发器

```
收到消息 → 「这个任务会写文件吗？」
  不写 → 直接回复（零合规开销）
  写   → pre-flight（声明 → 亮灯 → 执行）
```

没有第三种情况。

---

## 铁律 2：唯一违规定义

> **写了文件但没声明 = 违规。**

---

## 铁律 3：写入声明格式

| 场景 | 格式 |
|------|------|
| M3（单文件，<20min） | `V9 写入声明：{路径} \| {动作摘要}` |
| M4（多文件/交付物） | 完整 `V9 已激活：` 块 |
| M5（跨Agent/长任务） | M4 + 预算 + 拆分计划 |

---

## 铁律 4：豁免清单

以下操作免声明：
- 追加运行日志一行（M3 收工）
- heartbeat 更新（状态文件 last_heartbeat 字段）

其他任何文件写入都需声明。

---

## 铁律 5：灰区处理

| 信号 | 判定 |
|------|------|
| 有具体对象 + 明确产出物 | 写文件 → pre-flight |
| 咨询语气（"怎么推进"/"能不能做"）| 不写文件 → 直接回复 |
| 无法判定 | 问用户确认，1 轮内决定 |

---

## 铁律 6：不写文件的场景

1. 解释概念 / 纯问答
2. 讨论方案（未到执行）
3. 评审 / 核对但不落盘
4. 日常闲聊
5. 巡检无异常 / 状态查询

巡检状态查询只读 `02-项目管理/巡检/health-latest.json`。健康判定必须同时满足 `summary.active=0` 与 `sources_failed=[]`；若 `sources_failed` 非空，即使没有 active 告警，也视为巡检源未看全。

---

## 铁律 7：执行中扩展

执行中发现要写更多文件 → 暂停、补充声明、再继续。
每次写入前自问：「我声明过要写这个文件吗？」

---

## 铁律 8：闲聊不是任务

闲聊不需要建卡，不需要声明，不需要收工。
`submitted` 不等于 `accepted`：未经验收方确认，不得声称"已验收"。
