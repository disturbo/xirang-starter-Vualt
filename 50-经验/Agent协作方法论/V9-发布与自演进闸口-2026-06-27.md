# V9 发布与自演进闸口

> 定位：给 V9.4 之后的自主推进划边界。Agent 可以提案、实现、测试和提交；不能自行放松约束、不能把未验收产物说成 accepted、不能把未接真实计费的 CNY 当账单。

## 1. Starter 发布闸

starter 是对外分发骨架，风险不是功能缺失，而是泄漏个人路径、项目私货、秘钥形态和未同步的版本口径。

| 闸口 | 必须满足 |
|---|---|
| 泄漏扫描 | `v9-starter-leak-check.py --root <starter> --json --strict` 无 p0/p1 |
| 版本同步 | starter README、主 Vault 版本索引、公开站点版本号一致 |
| 骨架边界 | 不包含真实项目资料、个人账号、私有路径、业务客户名 |
| release notes | 每次对外发布有 changelog 或版本记录 |
| 人工确认 | 首次公开、权限变化、秘钥规则变化必须走 HITL |

发布前固定命令：

```bash
python3 02-项目管理/脚本/v9-starter-leak-check.py \
  --root $HOME/Desktop/xi-rang-v9-starter \
  --json --strict
```

## 2. 自演进闸

Agent 可以改进 V9，但规则变更必须先证明自己不会降低约束。

| 动作 | 允许 Agent 自行做 | 必须人工确认 |
|---|---|---|
| 增加只读巡检源 | 可以，需 eval + reflex 自省 | 无 |
| 增加 negative fixture | 可以 | 无 |
| 把 warning 升为 block | 可以先提交设计和 eval | 翻 block 前确认 |
| 放宽 scope / 关闭 gate / 跳过 eval | 不可以 | 必须确认 |
| 修改 accepted 语义 | 不可以 | 必须确认 |
| 接真实账单 API | 可以做设计和只读 PoC | 写入成本口径前确认 |

## 3. 成本治理闸

当前口径保持：

```yaml
billing_status: usage_only | estimated | connected
```

| 层级 | 当前状态 | 规则 |
|---|---|---|
| token / usage | 可用 usage-only 事件记录 | 可作为工程消耗观察 |
| CNY | 未接真实账单 | 无 `billing_status=connected` + 平台 `cost_source` 时不得当账单 |
| 成本周报 | 可生成 | 必须区分 `usage_only` / `estimated` / `connected` |
| 真实计费 | 后置 | 接平台账单来源前只能做 usage token 最小闭环 |

成本事件宣称 `billing_status=connected` 时，必须同时提供平台成本来源，例如 `cost_source=platform_billing`、`provider_invoice` 或 `platform_usage`。否则 `agent-cost-events.py validate` 必须拒绝。

## 4. Handoff 与验收闸

| 状态 | 含义 |
|---|---|
| `status: done` | Agent 执行收工 |
| `review_status: submitted` | 提交给 reviewer，等待验收 |
| `review_status: accepted` | 由 `accepted_by != owner/author` 的验收方确认 |

任务卡从 submitted 到 accepted 必须使用 `v9_accept` 或等价的候选校验路径，不允许裸改。

M5 或显式 `handoff_required: true` 的任务，收工前必须有可接手 Handoff：

- status
- 产物路径或产物清单
- 验证结果或自查结果
- next action

## 5. 退出标准

一次 V9 自演进任务要宣称完成，至少满足：

1. 相关脚本通过 `py_compile` / `bash -n`。
2. harness eval 通过，且 `blocked_negative` 无下降。
3. 反射器 `sources_failed=[]`。
4. 任务卡 `review_status=submitted`，不自标 accepted。
5. 看板 Handoff 写清产物、验证和 next action。
