# V9 工具注册表

> 目的：让 V9 知道自己依赖哪些 harness 工具、由什么 eval 覆盖、最近一次验证是什么。工具注册表不替代测试；它负责把“谁在支撑哪条规则”写清楚。

## 注册原则

| 原则 | 说明 |
|---|---|
| 工具必须有 owner | 无 owner 的脚本只能是实验品，不能进入硬门禁 |
| 工具必须有输入输出 | 反射器、gate、eval 只消费结构化输出 |
| 工具必须有验证证据 | 优先引用 `v9-harness-eval-runner.py` 的 positive/negative fixture |
| 绿灯无感 | registry 是说明层，不给每次普通任务加字段税 |

## 上线门槛

任一工具进入 gate/hook/reflex 前，必须满足：

1. 有 `--json` 或明确 exit code 约定。
2. 至少有 1 个 positive fixture 和 1 个 negative fixture，除非它是纯聚合工具。
3. 对外部状态的失败必须显式报告为 `SOURCE_MISSING` / `SOURCE_FAILED` / `SOURCE_CRASHED`，不得静默绿灯。
4. 涉及验收、权限、分发、秘钥的工具，必须优先接入 negative fixture。
