# 息壤 V9 档位判定速查

> 确定"要写文件"后，用此表判定具体档位。

## 1. 判定表

```
要写文件？
  ├── 只改 1 个文件 + <20min ──→ M3
  ├── 改多文件 / 有明确交付物 ──→ M4
  └── 跨 Agent / >2h / 需拆分 ──→ M5
```

## 2. 档位对照

| 档位 | 文件数 | 时间 | 声明 | 状态文件 | 事件流 | 看板 | Handoff |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| M3 | 1 | <20min | 一行 | 不更新 | 不写 | 不更新 | 不写 |
| M4 | 2+ | 20min-2h | 完整块 | 亮灯+熄灯 | start+end | 更新 | 有下游时写 |
| M5 | 多 | >2h | 完整块+预算 | 亮灯+熄灯 | start+end | 更新 | 必写 |

## 3. 灰区速判

| 场景 | 档位 |
|------|:---:|
| 追加一行到已有文件（日志/事件流） | M3 |
| 修复一个文件的 bug（<50行改动） | M3 |
| 创建一个新文件（有 frontmatter） | M3 |
| 改 1 个文件但牵涉看板更新 | M4（因为看板也是文件）|
| 批量修改 3+ 文件的同一字段 | M4 |
| PRD + 原型 + 看板登记 | M5 |
| 需要调其他 Agent 协作 | M5 |

## 6. 升降档决策树

```
开始 M3
  → 发现需写第 2 个文件？
    是 → 升 M4（暂停 → 补声明 → 亮灯 → 继续）
    否 → 完成 M3 收工

开始 M4
  → 发现需跨 Agent？或预计 >2h？
    是 → 升 M5（补预算 + 拆分计划）
    否 → 完成 M4 收工

开始 M5
  → 执行中发现范围缩小到 1 文件？
    → 不可降档（已亮灯，完整收工）
```
