# V9 Workbench 综合插件方案

## 1. 定位

V9 Workbench 不是一个右侧状态面板，而是一整台面向 Vault 项目治理的综合工作台插件。

它的目标不是复制 LifeOS，而是把 LifeOS 的“侧边栏入口、工作台视图、周期/项目聚合、快速跳转”信息架构，改造为 V9 场景：

| LifeOS 面向 | V9 Workbench 面向 |
|---|---|
| 个人生活管理 | 项目迭代治理 |
| PARA 和周期笔记 | 基线、迭代、任务、Agent 协作 |
| 快速创建笔记 | 快速进入项目控制面和任务上下文 |
| Dataview 聚合 | V9 checker + Vault 只读扫描 |
| Pro 日历/任务增强 | 迭代日程、待办、风险和 AI 接手 |

一句话：

> V9 Workbench 是用户在 Obsidian 内操作 V9 的主控台，而不是 V9 的小挂件。

## 2. 布局原则

不把所有内容塞进右侧长卷轴。采用四层布局：

| 层 | 位置 | 作用 |
|---|---|---|
| 最左侧 ribbon 图标 | Obsidian 左侧图标栏 | 打开 V9 日历、打开 V9 主控台、打开/关闭 V9 Workbench |
| 中央主控台 | Obsidian 主编辑区 | 放沉浸式 V9 Agent Dashboard |
| 左侧工作台栏 | 文件夹区旁边的侧栏 View | 放轻导航、项目入口、任务、提醒、监控、AI 入口 |
| 主编辑区 | Obsidian 中央编辑区 | 打开具体项目文件、任务源文件、review、状态 JSON |

默认交互：

1. 点击“V9 主控台”：在主编辑区打开完整 Dashboard。
2. 点击“V9 工作台”：打开/关闭侧栏工作台。
3. 点击“V9 日历”：在左侧栏打开轻量日历，贴近文件浏览器区域。
4. 工作台默认开在左侧栏，不抢主编辑区。
5. 侧栏只展开“项目管理面板”，任务、日历、监控、图表、AI 默认折叠。
6. 点击任何条目只打开源文件，不自动写文件。

## 2.1 参考图拆解

本轮新增参考图给出的关键不是配色，而是信息架构：

| 参考图元素 | V9 吸收方式 |
|---|---|
| 顶部 `AGENT DASHBOARD` 标题 | 中央 `V9 AGENT DASHBOARD` |
| LIVE / last sync / Refresh | 状态徽标、同步时间、刷新按钮 |
| Overview / Today / Vault / Pulse 页签 | 已接真实切换：总览、今日、Vault、脉冲各自承载不同模块 |
| Token burn 横向进度条 | 改为 Iteration Risk Burn |
| Vault Health / Inbox / Task Flow 卡片 | 显示笔记健康、红黄灯积压、任务流 |
| Note creation heatmap | 项目文件近 35 天修改热力图 |
| Recent Notes / Agent Runs | 最近风险、Agent 职责运行态 |

因此 V9 Workbench 的完整壳是“双视图”：

1. **V9 主控台**：中央沉浸式仪表盘，适合总览和汇报。
2. **V9 工作台**：左侧常驻轻面板，适合日常导航和快速打开源文件。

当前主控台页签职责：

| 页签 | 当前承载 |
|---|---|
| 总览 | V9 总状态、风险燃烧条、健康卡、红黄灯、热力图、Agent Runs |
| 今日 | 今日任务流、可筛选任务看板、月视图提醒、AI 三模式上下文入口 |
| Vault | 项目管理面板、控制面进度、笔记状态监控 |
| 脉冲 | 可视化图表、风险脉冲、任务流、Agent Runs |

## 3. 核心模块

### 3.1 项目总览

显示：

- 当前迭代号。
- 总状态：正常 / 关注 / 异常。
- 回归测试通过数。
- 迭代治理红黄灯。
- 待办数量。
- 笔记监控问题数。

数据源：

- `~/Desktop/沙箱/v9-runtime/巡检/status-latest.json`
- `10-项目/README.md`
- 当前迭代工作台。

### 3.2 项目管理面板

显示：

- 迭代控制面文件完成度。
- 视觉预览状态。
- review 契约状态。
- 当前红黄灯 findings。
- Agent 职责映射。

下一阶段增强：

- 模块级进展矩阵。
- 范围项 included / excluded / carryover 分类。
- 封版归集进度。

### 3.3 任务与待办

第一版：

- 只读扫描 `10-项目/` 的 markdown checkbox。
- 显示未完成、已完成、逾期数量。
- 点击打开源文件。

下一阶段：

- 左侧分组：本迭代 / 基线 / 遗留项 / 待拍板。
- 状态筛选继续扩展：blocked、reviewing、accepted。
- 看板视图继续扩展：处理中、待验收、已关闭。

2026-06-27 已完成：

- `今日` 页签加入任务筛选：未完成、逾期、已完成、全部。
- `今日` 页签加入任务搜索，按任务文本或源文件过滤。
- 任务看板改为卡片式三列：逾期 / 待处理 / 已完成。
- 任务卡只显示模块、日期、标题、状态和源文件摘要，点击打开源文件。
- 参考 Kanban 卡片原则：用列表示状态，用卡片承载简短上下文、截止日期和来源，避免在看板里展开全文。

### 3.4 日历与提醒

第一版：

- 只读扫描 `10-项目/` 日期。
- 显示近期提醒和已过期日期。

下一阶段：

- 月视图当前已完成第一版。
- 迭代关键节点：范围冻结、封版、review。
- 与 Obsidian 日记 / Calendar / Tasks 插件协同。
- 可选系统提醒后置到桌面端。

2026-06-27 已完成：

- `今日` 页签加入当月月视图。
- 有提醒的日期显示数量，点击日期打开对应源文件。
- 下方保留近期提醒列表，避免月格信息过密。
- 新增左侧 `V9 日历` View，可通过最左侧 ribbon 图标打开，放在左侧栏靠近文件浏览器区域。
- 不使用 DOM hack 强行改 Obsidian 文件浏览器内部结构，避免破坏文件树稳定性。

### 3.5 笔记状态监控

第一版：

- 检查当前迭代文件 frontmatter。
- 检查双时间字段。
- 检查 `scope_status` 是否符合状态机枚举。

下一阶段：

- 缺 review、缺 preview、缺 owner、缺 valid_for。
- 孤立文件、过期事实、未封版基线修改。
- 一键生成“修复建议上下文”，但不自动修改。

### 3.6 可视化图表

第一版：

- 近 35 天项目文件修改热力图。

下一阶段：

- 模块进度热力图。
- Agent 活跃度。
- 风险趋势。
- 规则命中趋势。
- 迭代燃尽图。

### 3.7 AI 对话入口

第一版：

- 本地生成中文上下文包。
- 复制给智能体接手。
- 不接真实模型，不写 Vault。

下一阶段：

- 接入本地 V9 上下文摘要。
- 支持“问当前迭代”“问某模块”“问红灯怎么修”。
- 写入动作必须人工确认。
- 所有用户可见回答默认中文。

2026-06-27 已完成：

- `今日` 页签加入摘要、交接、修复建议三种上下文包模式。
- 输出可复制给右侧 AI / Claudian / 其他智能体继续对话。
- 插件仍不接真实模型、不写 Vault；真实模型对话保持 P2。

## 4. 数据层

V9 Workbench 只能读两类数据：

| 类别 | 位置 | 原则 |
|---|---|---|
| 运行态 | `~/Desktop/沙箱/v9-runtime/巡检/` | 由脚本写，插件只读 |
| 成果态 | Vault 内 `10-项目/`、`50-经验/` | 插件只读扫描，点击打开源文件 |

不允许：

1. 不把截图、缓存、日志写入 Vault。
2. 不在插件内运行巡检脚本。
3. 不自动改 V9 正文、基线、任务卡、迭代管理文件。
4. 不绕过人工拍板写 accepted、封版、规则晋升。

## 5. 插件工程形态

当前源码：

```text
$HOME/Desktop/沙箱/v9-status-panel-obsidian
```

运行安装：

```text
$HOME/Desktop/obsidianVault/.obsidian/plugins/v9-status-panel
```

后续建议重命名目录：

```text
$HOME/Desktop/沙箱/v9-workbench-obsidian
$HOME/Desktop/obsidianVault/.obsidian/plugins/v9-workbench
```

但重命名不作为当前 P0，避免打断已安装的验证链路。

### P2：AI 工作台化

后续：

1. 接真实模型对话框。
2. 支持读取当前打开文件和当前迭代上下文。
3. 支持生成 patch 建议，但写入必须人工确认。

### P3：桌面端

当出现以下信号再推进：

1. 需要跨 Vault / 跨项目切换。
2. 需要常驻后台巡检。
3. 需要系统通知、托盘、菜单栏状态。
4. 需要脱离 Obsidian 的独立 Agent 工作台。
