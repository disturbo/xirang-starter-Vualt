# 息壤 V9 成本治理

> 成本可观测性 + 熔断机制 + 周报。

## 1. 核心原则

- **三阶段持续追踪** — V9.2 从「收工单次写入」进化为 start → checkpoint → finalize 三阶段
- **增量(delta)语义** — 每次写入的 tokens/cost_cny 是本阶段增量，不是累计总额
- **生命周期事件与成本事件分离** — `task_end` 的 tokens/cost 固定填 0，避免双算
- **事件流 append-only** — 不修改已写入事件，只追加
- **汇总口径** — cost-fuse.py 只累加 `cost_checkpoint` + `cost_finalize`，忽略 `cost_start`

## 2. 三阶段成本事件（V9.2）

### 2.1 三阶段模型

| 阶段 | 事件类型 | 触发时机 | 是否计入汇总 |
|------|---------|---------|:---:|
| **start** | `cost_start` | v8_handshake 自动写入 | 否（仅标记起点） |
| **checkpoint** | `cost_checkpoint` | 关键阶段完成时手动写入 | 是（增量 delta） |
| **finalize** | `cost_finalize` | v8_end 自动写入 | 是（增量 delta） |

### 2.2 工具

```bash
# 自动：v8_handshake 自动调用 start
# 自动：v8_end 自动调用 finalize

# 手动：中间阶段 checkpoint
bash .standards/hooks/cost-event.sh checkpoint <task_id> <agent_id> [tokens] [cost_cny] [description]
```

### 2.3 参数说明

| 参数 | 位置 | 说明 |
|------|------|------|
| phase | $1 | `start` / `checkpoint` / `finalize` |
| task_id | $2 | 关联任务 ID |
| agent_id | $3 | Agent 标识符 |
| tokens | $4 | 本阶段增量 token（checkpoint/finalize） |
| cost_cny | $5 | 本阶段增量成本（checkpoint/finalize） |
| description/result | $6 | 阶段描述或结果 |

### 2.4 事件流位置

```
02-项目管理/智能体状态/智能体事件.jsonl   ← 主事件流（三阶段事件写入此处）
02-项目管理/agent-cost-events.jsonl     ← 兼容旧格式（agent-cost-events.py）
```

事件格式（V9.2 三阶段）：
```json
// cost_start — 不计入汇总
{"ts":"...","event":"cost_start","agent":"claudian","task_id":"T-20260531-01","model":"opus","tokens":0,"cost_cny":0}

// cost_checkpoint — 增量计入
{"ts":"...","event":"cost_checkpoint","agent":"claudian","task_id":"T-20260531-01","tokens":15000,"cost_cny":0.12,"description":"完成方案设计"}

// cost_finalize — 增量计入
{"ts":"...","event":"cost_finalize","agent":"claudian","task_id":"T-20260531-01","tokens":8000,"cost_cny":0.06,"result":"done"}
```

### 2.5 兼容旧格式

`agent-cost-events.py append` 仍可使用，写入 `agent-cost-events.jsonl`。cost-fuse.py 同时读取两个事件流进行汇总。

## 3. 熔断机制

### 3.1 cost-fuse.py

```bash
python3 .standards/cost-fuse.py T-20260528-01 --json
```

返回：
```json
{
  "task_id": "T-20260528-01",
  "cost_cny": 3.5,
  "ceiling_cny": 5.0,
  "pct": 70,
  "status": "warning"
}
```

### 3.2 阈值

| 阈值 | 状态 | 动作 |
|:---:|------|------|
| <60% | pass | 正常执行 |
| 60-99% | warning | 输出降级链信息（P1 advisory）+ msg-queue 通知 |
| ≥100% | fuse | 熔断阻断（P0）+ 降级建议 + msg-queue 通知 |

### 3.3 Gate 集成

- `pre-spawn` 门禁自动调用 cost-fuse
- 100% 触发 FUSE_BLOWN (P0) → spawn 被阻断
- 60%+ 触发 BUDGET_WARNING (P1) → advisory + 建议降级

### 3.4 模型降级链（V9.2）

cost-fuse.py v1.1 读取 `agent-contract.yaml` 中的 `fallback_model` 配置：

| Agent | 主模型 | 降级链 | auto_fallback |
|-------|--------|--------|:---:|
| Claudian | opus | sonnet → haiku | false |
| 阿莫西林 | o3 | o4-mini | false |
| 头孢 | deepseek-v4-pro | deepseek-v4 | false |
| 红霉素 | gpt-5.5 | o4-mini | false |
| WorkBuddy | 平台内置 | — | false |

- `auto_fallback: false` — 熔断时仅建议降级，不强制
- `auto_fallback: true` — 熔断时自动强制降级到链中下一个模型

## 5. 可观测性

### 5.1 成本周报

```bash
python3 .standards/v8-cost-observability.py --week current
```

输出：Agent 维度 + 模型维度 + Phase 维度 的成本汇总。

### 5.2 健康指标

```bash
python3 .standards/v8-health-metrics.py
```

输出：任务完成率 / 平均耗时 / 错误率 / 重试率。

### 5.3 事件流轮转

```bash
# 查看状态
python3 .standards/event-rotate.py status

# 归档超过 7 天的事件
python3 .standards/event-rotate.py rotate --days 7

# 恢复归档
python3 .standards/event-rotate.py restore --date 2026-05-20
```

归档位置：`02-项目管理/智能体状态/_archive/智能体事件-YYYY-MM-DD.jsonl`

## 6. Hermes 自动接入

当任务 ID 格式为 `T-YYYYMMDD-NN` 或设置环境变量 `V8_TASK_ID` / `HERMES_V8_TASK_ID` 时，Hermes runtime 自动写入成本事件到 vault。
