# V9 Workbench 插件 MVP 需求卡

## 1. 目标

把 V9.5 已经跑通的 `status-latest.json v1` 变成一个能实际承载项目治理的 V9 Workbench。它不是单纯状态灯，而是面向示例项目 EXAMPLE 月度迭代的只读项目工作台：项目进展、Agent 编排、任务/待办、日历提醒、笔记状态监控、热力图和 AI 上下文入口集中展示。

用户英文弱，状态面板、按钮、提示、报错和验收结论默认使用中文；状态 key、schema key、命令 id 等机器字段保留英文。

首选路线：先做 Obsidian 插件 MVP。原因是它离 Vault 最近、权限边界最小、能直接打开成果文件。桌面端保留为 P1：当需要跨项目、常驻后台、系统通知、多窗口或类 Reasonix 的独立工作台时再推进。

### 1.1 LifeOS 参考结论

本轮参考 `$HOME/Downloads/obsidian-lifeos-main` 的开源 LifeOS。可借鉴的是信息架构，不复制实现：

| LifeOS 做法 | V9 Workbench 借鉴 |
|---|---|
| 注册 Obsidian View | 注册中央 `V9 主控台` View 和侧栏 `V9 工作台` View |
| PARA + 周期笔记 | 项目基线 + 月度迭代 + AgentOps |
| Dataview 聚合任务/项目 | 只读扫描 `10-项目/` 和 `status-latest.json` |
| 快速创建/跳转 | 点击 badge、任务、监控项打开源文件 |
| 多语言 UI | 用户可见中文优先 |

## 2. 数据源

唯一数据源：

```text
~/Desktop/沙箱/v9-runtime/巡检/status-latest.json
```

必须兼容环境变量：

| 变量 | 含义 |
|---|---|
| `XIRANG_V9_INSPECT_DIR` | 直接指定巡检目录 |
| `XIRANG_V9_RUNTIME_DIR` | 指定 runtime 根目录，巡检目录为其下 `巡检/` |

必须先判断：

```json
{
  "schema_version": "v1"
}
```

不支持的 schema 只显示“版本不支持”，不猜字段。

## 3. MVP 界面

首屏是一台综合工作台，不再是状态弹窗：中央 `V9 主控台` 用于沉浸式总览，侧栏 `V9 工作台` 用于常驻导航。

| 元素 | 来源 | 行为 |
|---|---|---|
| 总状态 | `status`、`ui.headline`、`ui.summary` | 显示为正常 / 关注 / 异常三态 |
| 反射器 badge | `ui.badges[id=health]` | 点击打开 `paths.health_latest` |
| 回归测试 badge | `ui.badges[id=harness_eval]` | 点击打开 `paths.harness_eval_latest` |
| 迭代治理 badge | `ui.badges[id=iteration_ops]` | 点击打开 `paths.iteration_workbench` |
| 项目管理面板 | `parts.iteration_ops.summary/findings` | 显示控制面进展、红黄灯 |
| Agent 编排 | 迭代工作台 `Agent 职责映射` | 显示职责、owner、状态、边界 |
| 任务与待办 | 只读扫描 `10-项目/` checkbox | 显示未完成、已完成、逾期 |
| 日历与提醒 | 只读扫描 `10-项目/` 日期 | 显示近期日期提醒 |
| 笔记状态监控 | frontmatter 与 V9 状态机字段 | 显示缺字段、状态异常 |
| 可视化图表 | 项目文件 mtime | 近 35 天项目修改热力图 |
| AI 对话入口 | 本地工作台数据 | 生成中文上下文包，供智能体接手 |
| 刷新按钮 | 重新读取文件 | 不运行脚本，只读最新 JSON |
| 打开状态文件 | `ui.actions[id=open_status_latest]` | 打开 `paths.status_latest` |

中央主控台页签：

| 页签 | 状态 | 模块 |
|---|---|---|
| 总览 | done | 总状态、风险燃烧条、健康卡、热力图、红黄灯、Agent Runs |
| 今日 | done | 可筛选任务看板、月视图提醒、AI 三模式上下文入口 |
| 左侧日历 | done | `V9 日历` View 靠近文件浏览器区域 |
| Vault | done | 项目管理面板、控制面进度、笔记状态监控 |
| 脉冲 | done | 可视化图表、风险脉冲、任务流、Agent Runs |

视觉原则：

1. 绿色不打扰，黄色提醒，红色醒目。
2. 不做大屏仪表盘，不做营销式页面。
3. 不展示长 findings 列表；点击 badge 后去源文件看详情。
4. 缺文件、JSON 解析失败、schema 不支持时显示明确错误。

## 4. 非目标

首版明确不做：

1. 不运行 `v9-reflex-check.py`、`v9-harness-eval-runner.py` 或 `v9-status-summary.py`。
2. 不写 Vault 文件。
3. 不保存截图、临时日志或过程快照。
4. 不做后台定时任务。
5. 不做跨项目切换。
6. 不做系统通知。
7. 不做规则修复、自动补字段、自动提交。

## 5. 验收标准

| 标准 | 判定 |
|---|---|
| 读取契约 | 能读取 `schema_version=v1` 的 `status-latest.json` |
| 三枚 badge | Reflex、Eval、Iteration 均按 `ui.badges` 渲染 |
| 四个动作 | 支持 `ui.actions` 中的 open_file target |
| 路径跳转 | 所有跳转只使用 `paths` key，不手写拼接路径 |
| 错误态 | 缺文件、无效 JSON、schema 不支持均可见 |
| 只读 | 运行过程中不修改 Vault 和 runtime |
| 无过程文件 | Vault 内不新增截图、缓存、巡检快照 |
