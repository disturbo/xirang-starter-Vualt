# 知识管理规范 v1.0

> 所有智能体（@阿莫西林 / @Claude / @Codex / @Hermes）必须遵守

---

## 一、命名规范（强制）

| 概念 | 统一名称 | 禁止使用 |
|------|---------|---------|
| 新建项目 | **{项目名}** | 售后服务平台、交付服务管理平台 |
| 参考系统 | **奕派DMS** / **参考系统** | 售后融合DMS、售后服务平台、售后融合平台 |
| 合同名称 | 交付服务管理平台 | 仅用于技术协议等官方文档 |

**约束**：agents 在创建文件前必须检查路径，禁止使用已废弃的同义词。

---

## 二、目录结构规范

```
10-项目/{项目名}/{模块}/
├── 模块首页.md      ← YAML frontmatter 必填
├── PRD.md           ← 权威 PRD（如有）
├── 原型/            ← HTML原型（如有）
└── 知识沉淀.md      ← 资料摘要 + 设计决策

禁止在模块目录下创建：
❌ 业务文件/  ❌ 原型设计/  ❌ 图片/  ❌ 原始资料/
```

---

## 三、Agents 操作禁令

| 禁止行为 | 原因 | 违规后果 |
|---------|------|---------|
| ❌ 创建 `.hermes_project.md` | 污染图谱节点 | 立即删除 |
| ❌ 在 Vault 内 `git clone` | 产生隐藏 .git 目录 | 立即删除仓库 |
| ❌ 自动解压 zip 并为每个文件创建 md | 产生碎片垃圾 | 禁止自动化解压 |
| ❌ 创建 <500B 的 stub/redirect 文件 | 制造空壳节点 | 合并到 MOC 索引 |
| ❌ 在 20-资料/ 存放 PRD/规范 | 位置错误 | 迁移到 10-项目/ 或 30-规范/ |
| ❌ 使用「售后融合」「售后服务平台」作为项目名 | 命名混乱 | 统一为「参考系统」 |

## 四、文件创建 checklist

创建新文件前必须确认：

- [ ] 该内容是否已存在？（搜索 vault 确认）
- [ ] 命名是否符合术语规范？
- [ ] 文件大小是否 > 1KB？（<1KB 需人工确认必要性）
- [ ] 位置是否正确？（PRD→10-项目/，规范→30-规范/，资料→20-资料/）
- [ ] 是否使用了模板？（见 90-模板/）

## 五、月度巡检规则

每月由 @阿莫西林 执行：

1. 检查 20-资料/ 是否有新的 stub 文件
2. 检查是否有重复命名（{项目}/奕派混用）
3. 检查 MOC 链接是否断裂
4. 检查 90-归档/ 是否需要清理
